# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Pensmith is a tool for writing academic papers. It ships as a Claude Code plugin (Tier 1) and a portable Node CLI (Tier 2), and both tiers read the same workflow bodies, prompts, presets and references from the one `plugin/` directory (PLUG-02). The workflow is intake → research → outline → for each section { plan → write → verify } → compile → done. The architecture follows the [Get Shit Done](https://github.com/gsd-build/get-shit-done) plugin and the [gsd-plugin](https://github.com/jnuyens/gsd-plugin) repackaging.

- `PRD.md` is the spec and the source of truth. Check it before answering design questions, and cite the section (e.g. "per §7.6").
- `.planning/` is managed by GSD. It holds `PROJECT.md`, `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md`, `phases/<NN>-*/` (the current milestone's CONTEXT and PLAN docs) and `milestones/<ver>-phases/<NN>-*/` for shipped milestones.
- Status: v0.1.0 (phases 0–10) and v0.2.0 have shipped. v0.3.0 never started and was absorbed into milestone **v1.0.0 "Open Source Release"** (phases 17–27), which is in progress. Its locked decisions are D-V1-01..08 in `.planning/REQUIREMENTS.md`; Phase 17's are D-17-01..49 in `.planning/phases/17-runtime/17-CONTEXT.md` (D-17-46..49 are the review-round-2 additions). Check `.planning/STATE.md` for the current phase.
- Feature work goes through GSD (`/gsd:plan-phase <N>` and related commands). Don't build features outside that flow.
- Bug fixes come from `AUDIT-FINDINGS.md`, whose findings are numbered. Fixes go on branches named `fix/<N>-<slug>`, with commits like `fix(scope): … (#N)`. **`#N` is the audit finding number, not a PR number.**
- Code comments cite decision and threat IDs such as `D-12`, `D-17-43`, `T-3-10`, `WR-03`, `Pitfall 7` and `C4-HIGH`. These are defined in the phase CONTEXT/RESEARCH docs under `.planning/`. Grep there to find out why an odd-looking constraint exists before you "simplify" it.

## Commands

Requires Node ≥ 22.12 (the supported LTS lines are 22 and 24; CI runs both on Ubuntu, macOS arm64 and Windows). ESM with strict TypeScript (`NodeNext`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`).

```bash
npm ci
npm run build              # prebuild (generates gitignored bin/lib/version.generated.ts + bin/lib/verbs.json), then tsc → dist/
npm run lint               # eslint . (enforces the architectural chokepoints below)
npm run typecheck          # tsc --noEmit
npm test                   # scripts/run-tests.mjs: discovers tests/**/*.test.ts, isolates the data dir, runs `node --import tsx --test`
npm run test:tier-contract # Tier 1 ↔ Tier 2 equivalence gate (tests/tier-contract.test.ts + tests/tier-contract/)
npm run test:coverage      # c8; CI gate is 80% lines/statements, 66% functions/branches
npm run check              # full local gate: prebuild, lint, typecheck, build, tier-contract, test, manifest validation, bundle:check
npm run bundle             # prebuild, then esbuild → the committed plugin bundles in plugin/dist/ (scripts/bundle.mjs)
npm run bundle:check       # re-bundle and fail on any drift from the committed plugin/dist/ (CI)
npm run plugin:smoke       # CI-05: validate, install and launch the real plugin with Claude Code (CLAUDE_BIN or `claude` on PATH; no API key)
node scripts/plugin-session-check.mjs   # local only: live headless sessions with the plugin, evidence for PLUG-03/04/05/14 (needs a Claude login)

# Single test file / single test (the data dir is isolated here too — see below)
node --import tsx --test tests/doi.test.ts
node --import tsx --test --test-name-pattern="idempot" tests/doi.test.ts
node scripts/run-tests.mjs tests/tier-contract/        # a file or directory through the runner

# Run the CLI from source
npm run pensmith -- doctor
PENSMITH_NO_LLM=1 npx tsx bin/pensmith.ts status
```

Gotchas:
- On a fresh clone, run `npm run prebuild` (or `build`) before `lint` or `typecheck`. Both import `version.generated.js`, which doesn't exist until prebuild runs.
- Some tests spawn the **built** `dist/bin/pensmith.js` or `dist/mcp/server.js`: tier-contract, section-isolation, cli-stubs, doctor-exit-code, llm-transport, doctor-probes-cwd-independence, library-writer (the research → `paper://library` path), the Phase 19 acceptance suites (research-cli-lane, add-identifiers-cli, plan-research-cli, byo-new-cli, byo-new-pdfs, verify-retraction-cli), bare-chain, dry-run-workspace, dry-run-boundary, every test built on `tests/helpers/e2e-chain.ts` (the built CLI + an isolated data dir + the mock LLM, over the recorded e2e corpus), and installed-bin / installed-offline (which `npm pack` the package and `npm install -g` it from a loopback registry built from `package-lock.json` and the npm cache). Run `npm run build` after changing source, or those tests exercise stale code.
- **Three orthogonal modes (D-V1-01, S-15).** A real user is **live by default**: research, `add`, Pass 1/Pass 3 re-fetch, retraction and freshness checks, plagiarism and GPTZero talk to the real services with no env var set. *Sources offline* — `PENSMITH_OFFLINE=1`, or the test runner (`NODE_TEST_CONTEXT` / `PENSMITH_TEST=1`) unless `PENSMITH_NETWORK_TESTS=1` — replays exact recorded fixtures from `tests/fixtures/cassettes/` or fails closed (`OfflineEgressError`; Pass 1 records UNVERIFIABLE, which blocks compile and done); only an explicitly configured loopback LLM endpoint stays reachable. *LLM stubbed* — `PENSMITH_NO_LLM=1` — replaces every model call with a deterministic contract stub built from the request (schema-valid objects for structured slugs; for prose, `bin/lib/llm-text-stubs.ts` with its text in `plugin/templates/stubs/` — the drafter stub writes to the word target and cites every assigned citekey) and leaves the network mode alone. *`--dry-run`* does both, opens zero sockets, uses the labelled synthetic source provider (`10.0000/pensmith-dryrun.*`) and works in the dry-run workspace `./.paper-dry-run/` (below), never in `.paper/`. Offline and stubbed runs print one stderr banner each (a dry run's names its workspace); offline artifacts carry a marker line that never reaches an export.
- **Tests never touch the real data dir (CI-09, D-17-40).** `scripts/run-tests.mjs` points `XDG_DATA_HOME`, `LOCALAPPDATA` and `PENSMITH_TEST_DATA_DIR` at a per-run temp dir and sets `PENSMITH_TEST=1`. Under a test context `paths.ts` honours a platform data-dir variable only when it lies inside `os.tmpdir()`, else `PENSMITH_TEST_DATA_DIR`, else a per-process temp dir — so single-file runs and spawned CLI children are isolated too, and macOS (whose data dir derives from `HOME`) is covered. CI fingerprints the real data dir before and after the tests (`scripts/data-dir-fingerprint.mjs`, even when the test step failed), and `scripts/run-tests.mjs` does the same around every local run with a built `dist/`, failing the run on a change. A test that spawns the CLI *without* a test context must set the data-dir variables itself (and `HOME` on macOS).
- As root, as in cloud containers, the `tests/atomic-write.test.ts` case "preserves OLD content on rename/write failure" fails because `chmod 0o500` doesn't block root. It passes in CI.
- **The plugin bundles are committed (PLUG-02, D-23a-04).** `plugin/dist/{mcp/server.mjs, mcp/pdf-worker.mjs, hooks/<name>.mjs}` are self-contained esbuild bundles of `mcp/server.ts`, `bin/lib/pdf-worker.ts` and `hooks/*.ts` (a git-marketplace install runs no build). They inline `bin/lib/`, the `bin/cli/` verbs the MCP tools and hooks run (plan, write, verify, status, route-options, goal), `bin/lib/version.generated.ts` (the package.json version) and the locked dependencies, so after changing anything under `bin/` (lib or cli), `mcp/` or `hooks/`, the package.json version or a dependency in `package-lock.json`, run `npm run bundle` and commit `plugin/dist/`; `bundle:check` fails CI otherwise. Never edit a bundle by hand. Generate bundles only from a `node_modules` that `npm ci` made in *this* checkout: if `node_modules` is a symlink into another checkout, `rm node_modules` and `npm ci` here first — never run `npm install`/`npm ci` through the symlink. `tests/plugin-bundle.test.ts` asserts the 20 MB budget, builtins-only runtime imports and a boot from a copy of `plugin/` with no `node_modules`; the hook tests spawn the bundles (`tests/hooks/`).
- **Hooks (PLUG-14, D-23a-15).** `hooks/*.ts` are thin guarded entries (stdin JSON, `resolvePaperRoot` in hook mode, a `paths.ts` `hasCurrentLayoutPaper` check before any heavy `import()`, exit 0, protocol-only stdout); the logic is in `bin/lib/hooks/`, which never writes stdout. A hook never runs the legacy-layout move: a folder whose pre-v1 root STATE.json still awaits it is left byte-identical for the next CLI or MCP run. SessionStart prints one `hookSpecificOutput.additionalContext` line (never `systemMessage`) built only from validated or router-derived values — the router step without its file-derived attention detail (`nextActionOf(d, { quoteDetail: false })`) and HANDOFF's timestamp, enums and section id, never its free text — because `.paper/` may be shared and that text reaches the model; PreCompact writes HANDOFF.json v2 (`bin/lib/handoff.ts`, `migrations/handoff/`; assembly is total, and a HANDOFF written by a newer pensmith is never overwritten); PostToolUse (matcher `^mcp__(?:plugin_pensmith_)?pensmith__.*`: the plugin's server and the developer `.mcp.json` server Claude Code keeps in its place at the repo root) checkpoints to `pensmithDataDir()/checkpoints/<projectHash>.jsonl` (never `.claude/` or `.paper/`); Stop releases only this Claude session's MCP lock (`CLAUDE_CODE_SESSION_ID` reaches the plugin's MCP server and equals the Stop hook's stdin `session_id` — checked live).
- CI runs on Ubuntu, macOS arm64 and Windows. It fails if the build leaves the working tree dirty. Use `path.join`, not shell globs or hardcoded `/`. Line endings are LF. Symlinks become junctions on Windows (the installed-bin test does this).

## Architecture

### Two tiers, one set of workflow files

- **Tier 2 CLI**: `bin/pensmith.ts` (citty). The 16 verbs are **locked** in `bin/lib/verbs.ts` (`UX02_VERBS`), with no 17th verb; `VERB_ALIASES` rewrites aliases before dispatch, and an unknown verb or flag is a usage error (exit 2) with a did-you-mean. Each verb maps to exactly one `plugin/workflows/<verb>.md`, and every body needs a `<capability_check>` block (`scripts/validate-plugin-manifest.cjs` enforces this). Verbs get implementations through `REAL_VERB_LOADERS`, which points at `bin/cli/<verb>.ts` (`new` loads `bin/cli/intake.ts`). The global flags `--dry-run`, `--estimate`, `--yolo`, `--show-prompts`, `--runtime <provider>`, `--model <id>` and `--paper <name|path>` are pre-parsed before citty dispatches. New sub-features live under existing verbs, e.g. export and humanize are part of `done`. The entry guard is `bin/lib/main-guard.ts` `isMainModule(import.meta.url)` (realpath comparison), so `npm i -g`, `npm link` and symlinked roots run.
- **Exit codes and one-line failures (RUN-09, RUN-12).** `bin/lib/exit-codes.ts`: `0` OK, `1` EXIT_ERROR, `2` EXIT_USAGE, `3` EXIT_APPROVAL, `4` EXIT_BLOCKED, `5` EXIT_COST_CAP. An expected failure throws a `PensmithError` subclass (e.g. `LockTimeoutError`, the provider errors) and the dispatcher prints `pensmith: <message>` with its code — never a stack trace (`PENSMITH_DEBUG=1` shows one for unexpected errors).
- **Gates (RUN-28).** `bin/lib/gates.ts` is the one registry of interactive decision points, each with whether `--yolo` skips it and its non-TTY exit code. `--yolo` never skips the cost cap, `--estimate` proceed, detector consent, the active-paper pointer, or the own-source gates `byo-folder`, `zotero-collection` and `pdf-attach-unmatched` (a paper's config can name the reader's folder or collection; only the user approves it). `plan-research` (adding `plan N --research` hits to a section) is skippable.
- **Tier 1 plugin**: the `plugin/` directory (PLUG-02, D-23a-02) — the one canonical home of `workflows/`, `templates/` (prompts, citation styles, presets, stubs, the dry-run corpus), `references/`, `skills/` and `agents/` for both tiers. `plugin/.claude-plugin/plugin.json` holds the metadata and the inline stdio MCP server `node ${CLAUDE_PLUGIN_ROOT}/dist/mcp/server.mjs` (no `skills` or `hooks` key: the default scans load `skills/<name>/SKILL.md` and `hooks/hooks.json`); `plugin/hooks/hooks.json` runs `node ${CLAUDE_PLUGIN_ROOT}/dist/hooks/<name>.mjs` in exec form for SessionStart, PreCompact, PostToolUse and Stop; `plugin/skills/` holds `pensmith` (the one natural-language router) and the 7 user-invoked plumbing skills (`docs/PLUMBING.md`). The only generated files are the committed, drift-checked single-file bundles in `plugin/dist/`, built from `mcp/server.ts` and `hooks/*.ts` (the sources stay at the repo root with `bin/`), so a git-marketplace install needs no build. The root `.claude-plugin/marketplace.json` installs `./plugin`; the developer `.mcp.json` runs `node ${PWD:-.}/plugin/dist/mcp/server.mjs` (open Claude Code at the repo root; CONTRIBUTING has the caveats). `plugin/` never holds `bin/`, a CLAUDE.md or `node_modules/` (`tests/plugin-layout.test.ts`), and `scripts/validate-plugin-manifest.cjs` (`npm run validate:manifests`) enforces the spec shapes and rejects the old ones (`tests/fixtures/plugin-legacy/`). Tier 2 finds the same files through `paths.ts` `pluginRoot()` (the `plugin-assets` row). `mcp/` exposes `paper://` resources (state, outline, section/{n}, library, capabilities) and granular `paper_*` tools. It is a **thin shim** over `bin/lib/*`: handlers have at most 30 statements and use no fs or network. Its stdout is the JSON-RPC frame (PLUG-13): every line a verb or `bin/lib` module prints goes through `bin/lib/output-sink.ts` `out()`, which the MCP server (and each hook, once it finds a paper) points at stderr, and the read-only `pensmith_status` tool returns the exact `pensmith status` text through `withCapturedOutput`. Never `console.log` or `process.stdout.write` in `bin/` or `mcp/` (the `stdout-sink` and `mcp-stdout-graph` rows).
- **Routing**: a bare `/pensmith`, `next` and `resume` all go through `bin/lib/router.ts` `resolveNextAction`. It is a total, read-only function of the paper's files: STATE.json, each section's PLAN.md frontmatter, each section's DRAFT.md hash (against `verified_against_draft_hash`), OUTLINE.md's rows (which must list the sections STATE.json registers — `section-registry.ts`), `OUTLINE.rejected.md`, `COMPILE-INPUTS.json` (the content hashes compile used) and the mtimes of the compiled DRAFT.md and FINAL.md. It never throws and deliberately ignores HANDOFF.json. `plugin/skills/pensmith/SKILL.md` only maps natural language to verbs (a bare `/pensmith` asks the `pensmith_status` tool for the next step), and it must not duplicate router logic.
- **One step per invocation (GRND-18, D-18-28)**: bare `pensmith`, `next` and `resume` share `runNextStep` in `bin/pensmith.ts`. A decision runs its one verb, except a section's: `plan N` then `write N` then `verify N`, each only after the previous verb succeeded and the router names the same section's next stage (`write` normally verifies itself). The step stops at the first failing verb, exits with the last verb's code and prints `pensmith: ran <steps>; next: <step>` on stderr. `runRouted` adds the `--dry-run` loop (D-18-30): steps repeat until done/attention, a failure or gate refusal, or a decision that does not advance. An explicit verb (`plan` without a number included) never chains.
- **Parity**: `tests/tier-contract.test.ts` (and the cases under `tests/tier-contract/`) spawns both tiers and asserts they behave the same. If they diverge, fix the shipped code in one tier. Don't add a normalizer, loosen the assertion or skip the test (see CONTRIBUTING.md "Tier contract — do not skip").

### Paper workspace

A paper lives in `.paper/` under the **project root** — the folder that contains `.paper/` (D-17-32). Every loader (`loadState`, `loadOutline`, `loadSection`, `loadLibrary`, `config.ts`, COSTS, SESSION.log) takes the project root and resolves `.paper/` itself. The active paper is resolved once per invocation (`paths.ts` `resolvePaperRoot`, S-21): `--paper` or `PENSMITH_PAPER_ROOT` (the project root), then a cwd containing `.paper/`, then a new paper for `new` or a bare run with an assignment file, then the `pensmith open` pointer (read-only verbs follow it with a banner; mutating verbs ask, or refuse with exit 2; `--yolo`, the MCP server and the hooks never follow it), and only with no pointer a new paper for a bare run whose stdin is a pipe (a piped text under 3 words is refused as not an assignment). `.paper/` contains `STATE.json`, `INTAKE.md`, `config.toml` (read and written only by `bin/lib/config.ts`, `schema_version` + migrations), `LIBRARY.json`, `RESEARCH.md`, `OUTLINE.md`, `CITATIONS.bib`, `CITATIONS.ris`, `SESSION.log` (the per-paper session log), `COSTS.jsonl` (the per-paper cost ledger), `sections/<NN>[a]-<slug>/{PLAN,DRAFT,VERIFICATION}.md` (a section a re-outline inserts after §N keeps N plus a letter, `01a-<slug>/`, and is found by its slug — never renumbered; GRND-09), `sections/_archive/` (sections a re-outline dropped), `OUTLINE.rejected.md` (the replies of an outline rejected after its corrective turn; the router reports attention instead of re-billing it), a section's `DRAFT.rejected.md` (a draft that cited a source outside its section twice, FEED-04), the compiled `DRAFT.md`, `COMPILE-REPORT.md`, `COMPILE-INPUTS.json` (the sections and section-file sha256s the compile used; the router's staleness check reads it, D-18-39), `FINAL.md` and `export/` (whose `CITATIONS.bib`/`.ris` hold only the cited sources). STATE.json is the one authority on a section's identity (`section-registry.ts`, D-18-38): OUTLINE.md's rows must list the same sections, and `pensmith outline` without `--force` applies a hand-edited OUTLINE.md with no model call. `OUTLINE.md` is the canonical 8-column markdown table `# | slug | title | role | depends_on | word target | assigned_sources | voice` (the legacy 6-column table still parses). A run from inside `.paper/` (or deeper) addresses the paper in the folder that holds it (`asProjectRoot`). A legacy root-level STATE.json or config.toml is moved into `.paper/` once, under lock.

**The dry-run workspace (GRND-19, D-18-29).** Under `--dry-run` (the pre-parse calls `setDryRunWorkspace`; children see `PENSMITH_DRY_RUN=1`) `paths.ts` `paperDir()` is `<root>/.paper-dry-run`, so every loader and writer follows it. `bin/lib/dry-run-paper.ts` prepares it under the paper's session lock: seeded from `.paper/` through `atomicWriteFile` (`.paper-dry-run/SEED.json` holds the fingerprint — relative paths, sizes, sha256; `SESSION.log`, `COSTS.jsonl`, `INTAKE.raw.local` and `export/` are not copied), kept across dry runs, re-seeded when `.paper/` changes. The real `.paper/` is read only to seed and is never created or written; a pre-v1 root layout is never moved by a dry run. `.paper-dry-run` folds like `.paper` (`asProjectRoot`, `hasPaper` — which counts a workspace only under a dry run), the global library never registers a dry-run paper, every export is named `.dry-run` (`.paper-dry-run/export/DRAFT.dry-run.<ext>`, `CITATIONS.dry-run.bib`), a read-only dry run (`status --dry-run`) seeds a missing workspace too, and `.paper-dry-run/` is gitignored. A normal run still refuses a Phase 17 dry-run paper marked `.paper/DRY-RUN.md`. App state lives **outside** the repo in `pensmithDataDir()` (`%LOCALAPPDATA%`, `~/Library/Application Support` or `$XDG_DATA_HOME`), because `.paper/` may sit in a sync folder. That state includes locks, the HTTP cache, the global library registry, the global `runtime.json` (the only place an LLM `endpoint` / `api_key_env` may be set), the active-paper pointer, and the global `session.log` that records a run with no paper (a paper's own SESSION.log and COSTS.jsonl live in its `.paper/`).

Section lifecycle is the PLAN.md frontmatter `status`: `planned → writing → written → verifying → verified | failed | unverifiable`. Outline approval writes a stub PLAN.md (`stub: true`, status `planned`) that routes to `plan`; a planned PLAN.md (no `stub`) routes to `write`; `write` verifies the section it drafted unless `--no-verify` (GRND-13, GRND-15), and one bare step runs a section's plan → write → verify (D-18-28). A write that fails containment sets `status: failed` plus `failure_reason` and keeps the older draft: the router reports attention, and verify, compile and the export gate refuse the section, naming `pensmith write N`. A failed verification of an unchanged draft is attention too (naming `plan N --revise` / `write N`), never a re-billed verify. PLAN.md frontmatter carries `schema_version` and is read through `frontmatter.ts` `loadFrontmatterDoc`. `verify` owns `verified_against_draft_hash`, and compile uses it to flag drafts edited after verification; the router recompiles when a section's draft or verification bytes (or the section set) differ from what `COMPILE-INPUTS.json` recorded, and `done` refreshes a FINAL.md that is older than the compiled `DRAFT.md`.

### Pipeline modules (bin/lib)

- **State**: `state.ts` composes `withLock` (`lock.ts`), `atomicWriteFile` and `loadAndMigrate`. Every persisted JSON carries a `$schemaVersion`. Adding a field to a persisted schema requires a new `bin/lib/migrations/<kind>/vN_to_vN+1.ts` and a version bump in the same change (S-20). The zod schemas live in `bin/lib/schemas/`.
- **Locks**: `lock.ts` `withLock` is an in-process FIFO per canonical resource, then one proper-lockfile attempt, then jittered 5→250 ms backoff until `timeoutMs`; the holder records `owner.json` (PID, host, times) in the lock directory, a dead holder on the same host is cleared at once, and a timeout throws `LockTimeoutError(resource, holderPid)` (RUN-22). It is not re-entrant. `session-lock.ts` is the separate per-paper session lock for mutating verbs (RUN-23).
- **Sources**: the registry `sources/index.ts` holds `crossref, openalex, arxiv, pubmed, semanticscholar, unpaywall, retraction-watch, books, zotero` (plus the synthetic dry-run provider under `--dry-run`). Every registrar adapter implements the three-way lookup (`lookupById` → `found | not-found | failed`, `fetchById` = `unwrapLookup`, a failed lookup throws `SourceLookupError`; `sources/lookup.ts`, D-19-05) and passes a `validate` shape check (`sources/registrar-response.ts`) so an error body is never cached, recorded or read as "not found"; failure reasons are complete lines with the fix (`HTTP 429 — rate limited; set PENSMITH_S2_API_KEY`). `retraction-cross-check.ts` sets `retraction_status` retracted / clear / unknown and never swallows a failure. `books.ts` is Open Library (+ Google Books for ISBNs); `zotero.ts` is the Web / local API client, `zotero-mcp.ts` the shared item normalizer, `zotero-ingest.ts` the ingest (MCP tool `paper_ingest_zotero_items`); `doi-ra.ts` asks doi.org which agency holds a DOI's prefix when Crossref answers 404 for a DOI `add` resolves (a DataCite DOI is then a failure that says so, never "not found"). The polite contact email comes only from `contact-email.ts` (row `contact-email`). `npm run live:sources` runs the adapter checks live; `docs/SOURCES.md` lists each service's floor and what it receives.
- **Research**: `bin/cli/research.ts` seeds 5–10 queries per scope from the brief (the topic disambiguator, clamped / padded by `query-expansion.ts`; `--scope`, `--queries`), ingests the user's own sources first (`[sources] byo_pdf_dir` through `byo-ingest.ts`, a `[sources] zotero_collection` pulled whole; the evaluator annotates them, never drops them; a folder outside the project and any collection are read only once this user approved them for this paper, `own-source-approvals.ts` — config.toml travels with a shared paper), then `research-orchestrator.ts` runs the pass: `adapter-plan.ts` (the preset's source preference, `allowed_databases`), discovery with per-adapter / per-query outcomes, `source-tier.ts`, `source-policy.ts` (`[sources]`), the source evaluator (candidates sent once, ≤ 150 per call; its rejection is respected — no keep-all fallback) and ranking. The prune question keeps the picks and accepts identifiers to add (identified like `add`). RESEARCH.md is the run log around a sources view of LIBRARY.json (`research-md.ts`). A run with no usable source exits 1, writes its log and leaves LIBRARY.json untouched; `research-sentinel.ts` keeps such a paper — and one whose only sources are the user's own (`new --pdfs`, `add`, Zotero) — at the research stage for the router. Kept sources with a DOI get their Unpaywall open-access PDF as `oa_url` (`open-access.ts`). `section-research.ts` is `plan N --research` / `revise N --research` (section N's PLAN.md only).
- **Library (BRDTH-01)**: `library.ts` `upsertSources` is the one writer of `LIBRARY.json` (schema v3: type, tier, relevance, why_relevant, retraction_status, `byo`, `zotero`, …) and renders `CITATIONS.bib` and `CITATIONS.ris` from it (`bibtex-write.ts` round-trips every name through `person-name.ts`; `verify` re-renders a bib that does not parse, `rerenderCitations`). Every ingest path (research, `add`, `plan --research`, bring-your-own PDFs, Zotero) calls it. It dedups by normalized DOI, then arXiv id / PMID / PMCID / ISBN, then the preprint ↔ version-of-record rule, merges the richer metadata and provenance, and never changes an existing citekey. Alternate DOIs are candidates only (VRFY-14). `compile` never rewrites the bib. `add` classifies its input first (`source-input.ts`) and identifies a PDF from its identifiers, a local GROBID, or its title and first author at the Pass-1 thresholds (`pdf-identify.ts`) — or refuses; a DOI found in a PDF's text counts only for the PDF's own work (its title and first author, or its title printed as the title), never a work it cites; `add <id> --pdf` attaches a PDF that does not show the work only at the user's word (`pdf-attach-unmatched`, recorded `byo.asserted`). Bring-your-own PDFs are hashed and their text is read only through a re-hash (`byo-text.ts`), by Pass 3 — and by Pass 2 only with `[verification] send_byo_passages = true`; `full-text.ts` says which sources have text Pass 3 can check (a non-asserted hashed BYO PDF, a DOI's open-access PDF — `oa_url`, set by `open-access.ts` only from Unpaywall's answer once that link served a PDF — or an arXiv id, whose arXiv PDF Pass 3 fetches).
- **Write**: the drafter only sees the section's `assigned_sources` (PRD §7.6), enforced by `drafter-input.ts` `assertDrafterInput`, which throws on any extra or missing field. `draft-containment.ts` `checkDraft` then rejects a draft citing any other key (every Pandoc citation form: clusters, `[-@k]`, `@{k}` and narrative `@k`): one corrective turn, then the draft goes to `DRAFT.rejected.md`, PLAN.md gets `status: failed` + `failure_reason`, and write exits 4 (FEED-04). The same corrective turn and failure path enforce the quote policy (GRND-14): the drafter request marks each source `full_text` from `full-text.ts` (a BYO source counts only while `byo-text.ts` still verifies its PDF), and `checkDraft` flags a direct quote attributed to a source without it (`quote-without-full-text`). Outline and plan are fed only sources the verifier can check (`source-context.ts` `verifierBlindSpot`, D-18-37, on the one route Pass 1 takes — `verify/pass1-identifiers.ts` `citationCheckRoute`: a Crossref DOI, a DataCite arXiv DOI, or an arXiv id / PMID / ISBN; retracted, synthetic, identifier-less and Zenodo/figshare/Dryad-only entries are withheld and named in a WARN and at the outline approval gate; VRFY-11 adds DataCite); the planner's allowed set is the outline allocation ∪ the current PLAN.md sources ∪ its `plan --research` additions, never just the previous plan's pick. Wave mode (`write` with no section) runs `scheduler.ts` `buildWaveGraph` (from `depends_on` plus `wave:` overrides) and `write-orchestrator.ts`. It is stateless and every node goes through the single-section drafter.
- **Verify**: `verify/pass1.ts` handles DOI/arXiv/PMID re-fetch plus the author/title fuzzy match → FABRICATED, MIS-CITED or UNVERIFIABLE (offline with no fixture, or any failed lookup — never "not found"); a Crossref record marked retracted blocks; an entry without a DOI is re-fetched at its own registrar (arXiv id → arXiv, `pmid` → PubMed, `isbn` → the books registries) and FABRICATED only when every one of them says not-found. `verify/pass3.ts` checks quotes → NOT_FOUND, against the source's hash-verified bring-your-own PDF first (`byo-text.ts`), then its open-access copy (the PDF Unpaywall lists for its DOI, else the arXiv PDF of its arXiv id). Passes 1 and 3 are deterministic and **blocking**. `pass2.ts` (claim support) and `pass4.ts` (orphans) are advisory only. `citation-token.ts` owns the one Pandoc citation grammar: the narrow bare `[@citekey]` token (smoother placeholders) and the broad reader of every form Pandoc renders as a citation (clusters `[@a; @b]`, locators, mixed-case and Unicode keys, author-suppressed `[-@k]`, braced `@{k}`, narrative `@k` outside code and link targets; D-18-40) that every gating or repairing consumer uses — Pass 1, containment, GATE-04, the Pass-3 quote extractor, compile's smoother masking (`replaceCitations`), revise, the density count and the export bibliography — so an unusual citation is never "absent". `verify/verdict-rows.ts` parses VERIFICATION.md.
- **Compile / done**: `compile.ts` holds the refuse-gate. `bin/cli/done.ts` and `exporter.ts` handle the humanizer wrap, Pandoc export and zero-trace output. `honesty.ts` covers GPTZero (explicit consent; `--yolo` never grants it) and `plagiarism.ts` covers DuckDuckGo phrase checks. CSL styles live in `plugin/templates/citation-styles/`.
- **HTTP**: `http.ts` `callOnce` is the one egress gate: network mode (`http-mock.ts` `networkMode()`), exact-fixture replay or refusal, DNS resolve + validate for every host, a per-request dispatcher pinned to the validated IP, the `--show-prompts` mirror, a streamed body under `maxBytes`, and a `kind:"http"` SESSION.log record. It follows 301/302/303/307/308 itself for GET/HEAD (≤ 5 hops, the full check and a fresh pin per hop, credentials dropped across origins, never for a model request; D-19-06), keeps per-host one-token rate buckets (no burst; lowered by a scholarly API's `X-Rate-Limit-*`, never raised; a declared rate slower than one request per 30 s marks the host exhausted; the token wait counts against the request timeout), holds the whole host after a 429 (its `Retry-After`, else ≥ 1 s and the declared interval), marks a host exhausted on a long `Retry-After` and opens a per-host circuit breaker after 3 consecutive 5xx responses or 3 requests in a row still throttled after their retries (D-19-08), caches only a validated answer under a key without secrets (D-19-10), and allows exactly the local services the environment enables (`local-services.ts`: the Zotero 7 local API, a loopback GROBID). PDF answers are checked by `pdf-response.ts` `checkPdfResponse`; pdf-parse runs in a terminable worker (`pdf-worker.ts`, SEC-02).
- **Prompts (RUN-26, FEED-05, D-18-03..05)**: every `plugin/templates/prompts/<slug>.md` is fixed instruction text — no `{{…}}` — with `inputs: [<tag>, …]` in its frontmatter and a `## Inputs` section describing each tag. A request is `bin/lib/prompt-request.ts` `buildPromptRequest(slug, values)`: `system` = the template (byte-identical on every call, always marked `cache_control` — a cacheable prefix once it reaches the model's minimum: 512 tokens on claude-opus-5, 4096 on claude-haiku-4-5), `messages` = one user message of `<tag>…</tag>` blocks in the order `PROMPT_INPUTS` declares, each value sent once, JSON built field by field. Inputs marked `untrusted` are wrapped in the one FEED-05 fence (`bin/lib/untrusted-fence.ts`); fence markers and closing tags inside a payload are neutralised. Structured stubs and the mock LLM read the same blocks (`requestHints`).
- **LLM**: `anthropic.ts` is the only module that calls a completion API — Anthropic Messages, OpenAI chat completions, and the OpenAI-compatible Ollama / vLLM / `openai-compatible` runtimes — and all I/O goes through `http.ts` with `llm: {endpoint}`. The SDKs are imported for **types only**. `llm-models.ts` holds the model table (default `claude-opus-5`; judgment slugs on `claude-haiku-4-5`) and the per-slug table; `llm-contracts.ts` maps each structured slug to one zod schema (native structured output where supported); `pricing.ts` never throws on an unknown model. The per-session cost cap (`[budget] cost_cap_usd`, default $5, `PENSMITH_COST_CAP_USD`) is checked before every call; every call is a `kind:"llm"` record in `.paper/SESSION.log` (keys never logged) and can be replayed with `resume --replay <id>`.
- **Educator/tutorial mode**: `tutorial.ts` is the **only** module that knows about `goal`. `tests/lint-tutorial-no-branch.test.ts` fails if `goal` or learning-mode vocabulary appears in any other `bin/lib` file or workflow body.

## Non-negotiables (PRD §14, §19)

- **Section-as-phase.** A paper is a project, a section is a phase, the outline is the roadmap, and compile is milestone completion. Each section's state is isolated by its `.paper/sections/<NN>-<slug>/` directory. Re-doing section 3 never touches the other sections (`tests/section-isolation*.test.ts` checks mtimes), and the verifier runs bounded per section. **This is the load-bearing design choice. Push back on anything that weakens it.**
- **Two-tier architecture.** Both tiers work from the same `plugin/` directory: its workflow bodies, prompts, presets and references (PRD §14 "Two-tier source-of-truth", amended by PLUG-02). Workflow bodies use `<capability_check>` blocks to degrade gracefully when Task, MCP or AskUserQuestion are unavailable.
- **Single-command UX.** `/pensmith` is the only command in the README quick start. Everything else is a power-user fallback.
- **The verifier blocks compile and export.** No FABRICATED, MIS-CITED, UNVERIFIABLE or quote-NOT_FOUND citation ever leaves a section. Pass 1 includes the author/title fuzzy match, because DOI integrity is necessary but not sufficient. Any path that makes an unparseable citation look "absent" instead of failing closed is a gate bypass (see AUDIT-FINDINGS #2, #3).
- **No trace in exported documents.** No metadata stamp, footer, offline marker or pensmith fingerprint (`tests/zero-trace-export.test.ts`). The README disclaimer (PRD §3) is the only disclosure.
- **Honest framing on detection.** The GPTZero score is shown for transparency, never as "we make it undetectable". The humanizer "improves prose"; it does not "evade detection".
- **Approval gates are on by default.** Outline approval and export confirmation are skipped only with `--yolo`; `--yolo` never skips the cost cap, the estimate confirmation, detector consent or the own-source approvals (a PDF folder outside the paper, a Zotero collection, an unmatched PDF).

## Deliberate user choices (don't second-guess)

- No metadata in exports. The user chose zero trace against Claude's recommendation, and we honor it.
- Style-match to past writing ships as an opt-in, built from plain statistics into a per-paper `.paper/STYLE.json`, with an honest dual-use disclosure in the README.
- The plagiarism check uses only free services (distinctive phrases via DuckDuckGo). Paid services were rejected.
- `--yolo` exists but is off by default.
- The user's installed `humanizer` skill (`~/.claude/skills/humanizer/`) is the humanize backend, and pensmith wraps it. If it's missing, `done` skips the humanize step.
