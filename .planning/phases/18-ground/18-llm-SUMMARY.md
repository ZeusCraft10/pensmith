# Phase 18, stream `llm`: Summary

Every template this stream owns is fixed instruction text with the per-call data sent
once, last, as fenced tagged blocks; the system prompt is always a `cache_control`-marked
prefix whose per-model minimum is recorded, reported by `status --config` and simulated by
the mock; caching is proven on repeated calls through the real CLI; the untrusted-data
fence has one home; every text slug has a contract-valid stub read from the request and a
data file, and the Phase 17 placeholder reply is gone.

## Decisions taken in the stream

- **Minimum-prefix table goes beyond D-18-05's list** where the claude-api skill states a value for a model already in the capability table: claude-sonnet-4-6 1024, claude-opus-4-7 2048, claude-opus-4-6 4096. claude-opus-5-5 is not in the skill's caching table, so it is reported against 4096 (listed: false) like any unknown model.
- **`status --config` token count** is `estimateTokens(template chars)` (chars/4), labelled `~N tokens`.
- **The evaluator's `venue`** is `"arXiv"` for an arXiv search result and `null` otherwise: `SourceCandidate` carries no venue (Phase 19 may add one). The template's preprint rule reads `venue` or an arXiv DOI. Retraction is no longer something the evaluator judges (the deterministic Retraction Watch cross-check runs after it, D-15); the `retracted` flag is not in the §3.3 payload.
- **Pass 2 / Pass 4 keep their NO_LLM short-circuit** (UNCLEAR rows, zero calls): the same result the claim-support / orphan-label stubs give, without building requests.
- **`hintsFromMessages` reads the last user turn that carries blocks**, so a corrective retry (which ends with a plain correction turn) still sees the data.
- **The mock drops its Phase 17 heuristics** (`Topic:` line, JSON regexes, `parseIntakeMd`); it derives hints only from the data blocks. No test in this worktree depended on the old heuristics.
