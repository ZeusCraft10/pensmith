# Phase 18, stream `sections`: Summary

Outline, plan and write now run on validated contracts fed by the intake brief and by each
section's own sources. Sections have stable ids (`3`, `1a`) and folders found by slug; a
re-outline never touches a kept section; write chains to verify; wave write names a broken
PLAN.md instead of dumping a schema error.

## Deviations and decisions taken in the stream

- **D-18-25 extended:** a failed section with a `failure_reason` routes to attention even when an OLDER DRAFT.md exists (the literal rule sent it to verify, which verified the old draft and silently hid the failed re-write). `verify` deletes `failure_reason` when it records its verdict. Found in the user-path run; test in `write-containment` and `pensmith-router`.
- **D-18-20:** the length target is config > brief > the assignment's stated length (`parseLengthWords`) > 1500. The extra step only matters for a pre-v1 INTAKE.md without `length_target_words`.
- **`readAssignedSources`** no longer exists: the drafter input is assembled by `assembleDrafterInput`, whose `readSectionPlan` throws `PlanUnreadableError` (one line, file + detail) on a malformed PLAN.md and `SectionNotPlannedError` (EXIT_USAGE) on a stub or absent PLAN.md; a `FrontmatterVersionError` passes through unchanged.
- **Legacy OUTLINE.md slugs are not normalised** (`01-introduction` stays): only model replies go through the `NN-` normalisation, so existing folders keep matching.
- **`readSectionState` keeps its 3-field shape** (the seam's frontmatter-versioning test deep-equals it); `readSectionInfo` adds `stub` and `failureReason`.
- **The outline approval precheck and the drafts check run before any state load**, so a refused `outline` never migrates STATE.json (the gates-registry "nothing touched" test).
- **`OutlineRow`/`OutlineDocument`** extend `ParsedOutlineSection`, whose new fields stay optional because seam-touched scheduler tests build `ParsedOutline` by hand.
