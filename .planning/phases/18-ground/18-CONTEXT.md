## Current behaviour (read in the code at the base commit)

- **Prompts.** All 14 `templates/prompts/*.md` interpolate per-call data into the instruction text with `interpolate()`; `section-planner.md` and `source-evaluator.md` embed the source list three times. `complete()` sends `cache_control` on the system block only for `cacheSystem` slugs, but the system text differs on every call (intake puts the whole interpolated template in `system`; plan/research/Pass 2/Pass 4 put it in the user message with a generic or empty system), so no two requests share a cacheable prefix. The fence constants live twice (`verify/pass2.ts`, `verify/pass4.ts`); the planner and drafter templates have no fence.
- **Intake** (`bin/cli/intake.ts`) takes only `--from <file>` or a cwd `assignment.*`; piped stdin, `@file` and paste are ignored. It never asks the PRD §7.1 questions: it renders the clarifier's structured reply (`Topic:`, `Discipline:`, the model's questions) as INTAKE.md. `parseIntakeMd` scrapes a topic heuristically. config.toml gets only `goal`/`pii_redaction`. The discipline preset file is never read by intake, outline, plan or write; `config.ts` reads it for `status --config` only, and `citations.ts`/`citation-density.ts`/`intake-parse.ts` carry their own discipline maps. The preset values diverge from PRD §8 (Biology APA, History Chicago author-date, counterargument never on).
- **Outline** (`bin/cli/outline.ts`) is already a structured slug (P17): OUTLINE.md is rendered from the validated `OutlineSchema` object, sections are registered in STATE.json. But the prompt still asks for YAML with `01-`-prefixed slugs and is fed only the topic, a length and a citekey list without abstracts; there is no semantic validation (unknown citekeys, word total, zero-source sections), no counterargument rule, no stub PLAN.md, no section folders, and `--force` renumbers everything. `parseOutline` drops `assigned_sources`.
- **Plan** (`bin/cli/plan.ts`) feeds the planner the outline row (title, deps, word target), library records and upstream briefs, but through a generic system prompt and a user message with the interpolated template; it filters invented citekeys silently, never validates claims, forces `status: writing`, and has no retry.
- **Write** (`bin/cli/write.ts`) validates a decoy `{sources: [], wordTarget: 300}` while the prompt gets `assignedSources '[]'`, `title = slug` and 300 words; no containment check, no chain to verify, no `--no-verify`. Wave write throws a raw ZodError on a malformed PLAN.md and warns `--max-parallel ignored` at 1.
- **Router/bare** runs exactly one verb per invocation; the section chain plan → write → verify takes three invocations. A failed outline is re-dispatched (and re-billed) by every bare run.
- **Dry run** (P17 D-17-46) works only in a folder with no paper; `.paper/DRY-RUN.md` marks a dry-run paper; text slugs return the `[PENSMITH_NO_LLM placeholder — …]` string, so a dry-run draft cites nothing.

## Decisions

Numbered D-18-NN. Later phases cite them like any other decision id.

### Execution protocol

- **D-18-01 — Four parallel streams, one seam patch, one integration pass.** Streams `intake`, `sections`, `llm`, `workflow` (18-PLAN.md §5) run in separate worktrees from the plan commit. Each owns disjoint paths; shared hot files are edited only in the regions 18-PLAN.md §6 assigns. A stream calls only APIs that exist at the base, APIs it creates, and seam APIs. Anything that can only pass once all four have merged (the mock-LLM e2e chain, the full dry-run chain, the plan/write cache proof) is an **integration-pass** task (18-PLAN.md §7), not a stream task.
- **D-18-02 — Seam S-A is one patch applied first, byte-identically, by every stream.** `seams/18-seam-S-A.patch` (verified at the base commit: `npm run lint`, `npm run typecheck`, `npm run build` and the full `npm test` green apart from the documented root-only atomic-write case) adds the contracts several streams consume before any of them merges:
  - `bin/lib/untrusted-fence.ts` — the one FEED-05 fence;
  - `bin/lib/prompt-request.ts` — the one prompt request layout (D-18-03) with the per-slug input table;
  - `bin/lib/disciplines.ts` + `templates/presets/disciplines.json` — the one preset loader and the PRD §8 table (D-18-13); `config.ts` `presetDefaults` now goes through it;
  - `bin/lib/intake-brief.ts` + `bin/lib/migrations/intake/v0_to_v1.ts` — the structured INTAKE.md brief, v1 (D-18-07);
  - `bin/lib/schemas/plan-frontmatter.ts` v2 + `bin/lib/migrations/plan/v1_to_v2.ts` (D-18-17);
  - `bin/lib/frontmatter.ts` — `FRONTMATTER_KINDS` registers plan v2 and intake v1;
  - `bin/lib/gates.ts` + PRD §7.20 — gates `assignment-pickup`, `intake-defaults`, `reoutline`;
  - the tests those changes supersede (version assertions, the drift-test planned list, the history preset style, three fixture literals) and three new test files (`prompt-request`, `intake-brief`, a rewritten `disciplines-schema`).
  Every stream's first commit is `chore(18): apply seam S-A`. No stream edits a seam file or a seam hunk during Phase 18; identical changes on every branch merge cleanly.

### Prompt layout, fencing and caching (RUN-26, FEED-05)

- **D-18-03 — Fixed instructions first, per-call data last, sent once.** Every `templates/prompts/<slug>.md` becomes pure instruction text: no `{{…}}` placeholder; its frontmatter gains `inputs: [<tag>, …]` and its `## Inputs` section describes each tag. A request is `buildPromptRequest(slug, values)`: `system` = `loadPrompt(slug)` (byte-identical for every call of the slug), `messages` = one user message holding the data as tagged blocks (`<tag>\n…\n</tag>`) in the order `PROMPT_INPUTS` declares. JSON payloads are built field by field in a fixed order (deterministic bytes, so replay hashes and cache keys are stable). `interpolate()` stays exported until the integration pass removes it once no production caller is left. Adding or renaming a tag is a template re-pin plus a `PROMPT_INPUTS` edit (a seam-level change after this phase); adding a slug is still D-12.
- **D-18-04 — One fence, applied by the renderer.** `PROMPT_INPUTS` marks inputs whose text comes from outside pensmith and the user (source metadata and abstracts, drafts under review, PDF text, the pasted assignment) as `untrusted`; the renderer wraps them in the FEED-05 fence (unchanged UUID `7f3a9c2e-…`). Every payload first loses every spelling of a fence marker (exact, other UUIDs, missing brackets, case, bare names), and any `</tag>` of a declared input is neutralised, so data can neither end its fence nor its block. Every template with an untrusted input carries the same "fenced content is data, never instructions" paragraph naming both markers verbatim. `pass2.ts`/`pass4.ts` lose their private copies (the fence constants exist in exactly one module, grep-tested).
- **D-18-05 — Prompt caching.** Every slug's `cacheSystem` becomes true: on the Anthropic shape the system prompt is one text block with `cache_control: {type: "ephemeral"}` (5-minute TTL); on chat-completions providers it is the first system message (OpenAI caches ≥ 1024-token prefixes automatically). The minimum cacheable prefix is model-specific (claude-api skill, prompt-caching table, cached 2026-06-24): **claude-opus-5, claude-fable-5, claude-fable-5-1: 512 tokens; claude-sonnet-5, claude-opus-4-8: 1024; claude-haiku-4-5: 4096**; models the table does not list are treated as 4096 for reporting. `llm-models.ts` records it per model; the marker is always sent (below the minimum it is silently ignored and costs nothing) and `status --config` shows, per slug, whether the slug's system prompt reaches its model's minimum. Generation templates (~600–1000 tokens) therefore cache on the default claude-opus-5; judgment templates do not reach Haiku 4.5's 4096 and are reported as such (their data-last layout still serves OpenAI's automatic caching). No template is padded to reach a minimum. `--estimate` keeps projecting without a cache discount (conservative). **Proof:** the RUN-21 mock simulates caching per model minimum (exact-prefix keys per breakpoint, 5-minute TTL, `cache_creation_input_tokens`/`cache_read_input_tokens`, OpenAI `prompt_tokens_details.cached_tokens`); a repeated call of the same slug in one run shows `cache_read_input_tokens > 0` in the captured response, SESSION.log (`cache_read_tokens`) and COSTS (read priced at 0.1× input). RUN-26 is marked Complete at close if that holds for claim-support (llm stream, with a slug model override) and for section-planner and section-drafter (integration pass).
- **D-18-06 — Contract stubs read the request, like a model (GRND-19).** `promptHints(content)` (seam) turns a request's blocks into a hint object (JSON blocks parsed, text blocks as strings). Structured stubs (`llm-stubs.ts`) take `stubHint: requestHints(req)` from the call site; the mock LLM derives the same object from the request body, so stubs and mock agree. Text stubs move to `bin/lib/llm-text-stubs.ts` with their prose in `templates/stubs/text-stubs.json` (asset root; no topic words in `.ts`): the drafter stub writes paragraphs to the section's word target and cites every assigned citekey at least once (none when none are assigned), never quoting; the smoother stub passes the boundary through; revise-swap returns a valid remove recommendation; the tutorial stubs return short labelled text. The `[PENSMITH_NO_LLM placeholder — …]` string is gone. Each structured slug's stub stays next to its contract owner's region (intake-clarifier: intake stream; outline-author and section-planner: sections stream; the rest: llm stream).

### Intake (GRND-01..06)

- **D-18-07 — INTAKE.md is the versioned project brief.** Frontmatter v1 (`IntakeBriefSchema`, seam): `schema_version`, `topic`, `thesis`, `discipline` (preset slug), `paper_type` (argumentative | persuasive | analytical | expository | literature-review | research-report | lab-report | summary | primer | other), `mode` (draft | outline), the tutorial.ts fragment (spread unnamed), `class` (default Unfiled), `counterargument` (yes | no | auto), `length_target_words` (int or null), `citation_style` ('' or one of the 8 CSL keys), `sectioning_notes[]`, `pii_redaction`, `style_match`, `assignment_source` {kind: file | at-file | stdin | cwd | paste | thesis-seed | none, name}, `follow_ups[]` (≤ 3 {id, question, answer}). Body: `# Intake`, `## Assignment` with the assignment between `<!-- pensmith:assignment:start/end -->` markers (verbatim, or redacted when PII is on), and a rendered `## Questions and answers`. `renderIntakeDocument`/`readIntakeBrief` (seam) are the only writer format and reader; readers go through the CONF-04 loader. A v0 INTAKE.md migrates in memory (topic and discipline from its `Topic:`/`Discipline:` lines). `parseIntakeMd` becomes a thin wrapper over the brief (research keeps calling it, and its `topic` is the structured topic, never clarifier text). config.toml `[project]` mirrors `mode`, the fragment, `class`, `discipline_preset`, `citation_style`, `length_target_words`, `counterargument_required` (only for a yes/no answer), `pii_redaction`, and `[style] match_past_writing`/`samples_dir`. PRD §7.1, §7.2 and §13 name `.paper/INTAKE.md` as the brief (S-08).
- **D-18-08 — Where the assignment comes from, in order.** `--from <file>`; a positional `@path` (`new @notes.md`); piped stdin; a cwd `assignment.{txt,md,pdf}` (bare `pensmith` and `new`); an interactive paste in a terminal. Supported types: `.txt`, `.md`, `.pdf` (PDF through `pdf-text.ts`, text only — no `%PDF-` byte reaches `.paper/`); anything else fails with the supported-types list; a missing file fails with not-found; empty input fails. **Stdin rule (keeps D-17-36's "never hang"):** stdin is read as the assignment only when no file source was given, stdin is not a terminal, its `fstat` is a FIFO or regular file, and `PENSMITH_PROMPT_MODE` is not `numbered` (then stdin carries answers); reading uses a 2 s first-byte timeout (no byte and no EOF → no stdin assignment) and a 1 MiB cap, then reads to EOF. A cwd pickup asks the `assignment-pickup` gate (`Use the assignment file in this folder?`) in a terminal; `--yolo` and a run that cannot prompt use it and print its name; "no" falls through to paste. Several `assignment.*` files: a select in a terminal, EXIT_USAGE naming them otherwise. No assignment in a run that cannot prompt: EXIT_USAGE `no assignment found`, nothing written. The resolver (`paths.ts resolvePaperRoot`) treats a piped stdin like an assignment file for a bare run (RUN-14 row 3).
- **D-18-09 — The §7.1 battery is asked deterministically, before and after one clarifier call.** Questions (id, flag, answers-file key): discipline (`--discipline`), mode (`--mode`), the tutorial.ts question (its flag and key come from tutorial.ts), class (`--class`), counterargument (`--counterargument yes|no|auto`), style-match (`--style-samples <dir>`, `no`/blank = off), PII redaction (`--pii-redact`/`--no-pii-redact`), length (`--length <words>`), citation style (`--citation-style`). `--answers <file.toml>` supplies any of them (read through a `config.ts` helper — the config-toml chokepoint owns smol-toml) plus `[follow_ups]`. Order: resolve the assignment → collect flag/answers-file answers → **if the run cannot prompt, lacks `--yolo` and any battery question is unanswered: EXIT_APPROVAL through the `intake-defaults` gate, naming them, before any model call or write** → `assertLlmConfigured` → disclaimer → PII redaction → the clarifier call → in a terminal, each unanswered question with the clarifier's (or preset's) suggestion as default, then the ≤ 3 follow-ups; under `--yolo`, the suggestions are accepted and printed (`intake-defaults` yolo choice) → write STATE.json, INTAKE.md, config.toml, STYLE.json (opt-in), registry entry (with the answered class). Follow-ups a run cannot ask record the clarifier's suggested answer and say so in the Q/A section. Defaults: discipline = clarifier suggestion normalised by `normalizeDisciplineSlug`, mode draft, class Unfiled, counterargument auto (a preset `ask` asks in a terminal), style-match off, PII off, length = the assignment's stated length (`N-word`, `N words`, `N pages`×300) else the clarifier's else 1500, citation style = the deterministic override (D-18-11) else the clarifier's else the preset default. `bin/cli/intake.ts` may import `ask()` (the gate-registry chokepoint row gains it, as D-17-36 anticipated). The question list is built in `bin/lib/intake-questions.ts` (the Tier-1 `paper_get_intake_questions` tool reuses it in Phase 23); it composes the tutorial.ts question without naming it, so the lint-tutorial allowlist is unchanged.
- **D-18-10 — The clarifier only suggests.** `IntakeClarifierSchema` becomes `{topic, discipline, paper_type, thesis, length_target_words (0 = not stated), citation_style ('' or a style name), sectioning_notes[], follow_ups[≤3]{id, question, suggested_answer}}`; inputs `disciplines` (the preset slugs and names), `answers` (what flags already fixed), `assignment` (fenced). Its reply is never persisted as INTAKE.md; only the brief built from answers is. The template's own example reply parses through the contract and, fed through intake, never becomes the topic verbatim or INTAKE.md.
- **D-18-11 — Plain-English overrides and style aliases (GRND-04).** `bin/lib/intake-overrides.ts` parses the assignment and every answer deterministically: citation style ("use MLA instead of APA" → the style after use/in/follow; "APA style", "APA 7") and sectioning notes ("I need a literature review section before methods"). Style names match case-insensitively through the alias table in `schemas/config.ts` (APA, APA 7, MLA, MLA 9, Chicago → chicago-notes-bib, Chicago Notes-Bibliography/NB, Chicago Author-Date/AD, IEEE, AMA, Vancouver, Harvard); an unknown name fails listing the 8 styles. Sectioning notes go into the brief and the outline request.
- **D-18-12 — PII (GRND-05).** Redaction stays opt-in. The only path by which user PII enters the pipeline is intake (assignment, answers, thesis seed, follow-up answers); with redaction on, all of them are redacted before the clarifier call and before INTAKE.md is written, the raw text goes only to the gitignored `INTAKE.raw.local`, and every later step reads the redacted brief — so no model request in the chain carries raw PII (asserted over every captured mock request of new → research → outline → plan → write). `pii.ts` gains names with middle initials, hyphens and particles, a labelled-ID class, textual dates, and exclusions (entity head nouns such as Revolution/War/Treaty/Republic/Empire/University/Act, terms from the topic line, month fragments like "Due March"). Identifiers (UUIDs, DOIs, ISBNs, arXiv ids, ISO timestamps) are never rewritten — which also fixes SESSION.log's `deepRedactPii` mangling paperIds.
- **D-18-13 — One preset loader (GRND-06).** `disciplines.ts` (seam) reads the PRD §8 table (plus `sociology`, which PRD §8 now lists): per preset `name`, `aliases`, `defaultTone`, `defaultCitationStyle`, `alternateCitationStyles`, `sourcePreference` (ids `arxiv, semanticscholar, openalex, pubmed, crossref, books, jstor, psycnet, nber, philpapers`; adapters for the last five are Phase 19's), `sectioningConvention`, `counterargDefault` (on | off | ask), `densityPerParagraph` {min, max}. `resolveDiscipline`/`resolveLayered` apply preset < intake answer < config.toml < CLI flag and name the winning layer. Consumers: intake (defaults, suggestions), outline (sectioning convention, counterargument default), plan and write (tone), `citations.ts resolveStyleName`, `citation-density.ts` (per-paragraph band), `intake-parse.ts` (normalisation), `config.ts` (status --config, done in the seam). A `discipline-literals` chokepoint row (intake stream) forbids discipline-slug literals outside `disciplines.ts`.

### Outline and sections (GRND-07..10, FEED-03)

- **D-18-14 — One outline contract.** The model returns JSON `{thesis, sections: [{n, slug, title, purpose, depends_on, estimated_word_count, assigned_sources, role, voice?}]}` validated by `OutlineSchema` (roles = `SECTION_ROLES`: intro, body, counterargument, rebuttal, counterargument-rebuttal, conclusion) and sent as native structured output; the tolerant parser accepts fenced JSON or YAML with prose around it. A slug arriving with an `NN-` prefix is normalised to the bare slug (`01-introduction` → `introduction`), and a fresh outline is numbered 1..N in the order the model lists its sections (the model's `n` is not trusted; a re-outline numbers per D-18-18). Inputs: `brief` {topic, thesis, discipline, paper_type, length_target_words, sectioning_convention, sectioning_notes, counterargument_required, min_sections 3, max_sections 7}, optional `existing_sections` (re-outline: the kept sections' slugs, titles and roles, so the model can keep slugs), `sources` (fenced: citekey, title, first_author, year, tier or null, abstract ≤ 300 chars). The canonical OUTLINE.md table becomes `| # | slug | title | role | depends_on | word target | assigned_sources | voice |`, `#` is `N` or `Na`; `parseOutline` reads it (and the legacy 6-column table) and returns `suffix`, `role`, `assigned_sources` and `voice` per row. The template's own Output Format example parses through the production parser into ≥ 2 sections, bare and fenced.
- **D-18-15 — Outline validation, one corrective retry, no silent re-billing.** Before the approval gate: slugs unique; depends_on exist, no self-reference, no cycle; every assigned citekey in LIBRARY.json; word targets sum within ±20% of the length target; at most 2 sections other than intro/conclusion with no source; the counterargument rule when required (D-18-19). A violation gets one corrective turn quoting every error. Still invalid: EXIT_ERROR naming the errors, the raw reply (both attempts) saved to `.paper/OUTLINE.rejected.md`, nothing else written — an existing OUTLINE.md stays byte-identical, even under `--yolo`. The router returns `status`/`attention` with a detail naming `pensmith outline` while `OUTLINE.rejected.md` exists and no sections are registered, so a bare run never re-bills; a successful `pensmith outline` deletes it.
- **D-18-16 — Section identity: number plus optional letter; the folder is found by slug.** STATE.json sections become `{n, suffix?, slug}` (state v3, identity migration v2→v3). `bin/lib/section-id.ts` parses/formats `1`/`1a`, orders `(n, suffix)`, and names folders `NN[a]-slug`. `paths.ts` resolves a section's folder by its slug (the one `sections/<NN>[a]-<slug>` directory), falling back to `NN-slug` for a folder not yet created, so every existing `(n, slug)` caller keeps working; creation takes the suffix explicitly. Section arguments accept `1a` (`plan 1a`, `write 1a`, `verify 1a`, `paper://section/1a`). The router, status, estimator, compile and the scheduler order by `(n, suffix)`.
- **D-18-17 — Stub PLAN.md and plan frontmatter v2.** v2 (seam) adds optional `suffix`, `purpose`, `role`, `word_target`, `voice`, `stub`, `failure_reason`; the v1→v2 migration only rewrites the version line. Outline approval writes, per section, `sections/NN[a]-slug/PLAN.md` with `stub: true`, `status: planned`, section, slug, title, purpose, role, depends_on, word_target, voice (when given), assigned_sources, and a body `## Outline entry` with the purpose. Registration of an existing valid OUTLINE.md creates missing stubs only.
- **D-18-18 — Re-outline keeps every unchanged section untouched.** Re-outlining a paper that has any DRAFT.md needs `--force` plus the `reoutline` gate (a terminal confirms; `--yolo` answers yes only together with `--force`; without a terminal and `--yolo` it refuses, EXIT_APPROVAL). The model receives `existing_sections`. Matching is by slug: a kept slug keeps its number, suffix, folder and every file byte- and mtime-identical, and its OUTLINE row shows the new title/purpose/role/deps/word target with the kept number and its PLAN.md `assigned_sources` (PLAN.md is the authoritative map, FEED-04). A new section gets the previous section's number plus the next free letter when a kept section follows it (after §1 → `01a`), the next integer after every kept section when none follows, and the largest free integer below the first kept section when it comes first (refused if none is free). A dropped section's folder moves to `sections/_archive/<NN>[a]-<slug>/` (a timestamp suffix if that exists) and leaves STATE and OUTLINE. No folder is ever renamed or renumbered.
- **D-18-19 — Counterargument resolver.** `bin/lib/counterargument.ts` decides `required` with its source: `outline --no-counter` → false; config.toml `counterargument_required`; the intake answer yes/no; `auto`: the paper type (argumentative/persuasive → true; lab-report/summary/primer → false); else the preset default (`on` → true, `off`/`ask` → false). When required, the brief says so and the outline must hold a `counterargument` and a `rebuttal` section or one `counterargument-rebuttal` section; after the one corrective retry the outline refuses — before the approval gate, including under `--yolo` — with `counterargument + rebuttal section required (§7.4); use --no-counter to disable`, registering nothing. The v0.1.0 archive marks OUTL-02 as not implemented until Phase 18.
- **D-18-20 — The paper brief downstream.** Outline, plan and write read the brief through `readIntakeBrief`; the effective thesis is the approved outline's thesis when OUTLINE.md has one, else the brief's; the length target is config.toml > brief > 1500; the discipline comes from `resolveDiscipline` (flag/config/intake).

### Plan and write (FEED-01, 02, 04, GRND-12, 13, 15, 16)

- **D-18-21 — Source context builder.** `bin/lib/source-context.ts` (pure: no fs, no network) maps LIBRARY entries and a citekey list to `SourceContextRecord {citekey, title, authors[≤5], year|null, venue|null, abstract (≤ 800 chars)|null, tier|null, full_text: boolean}`, in the citekey order given, dropping keys not in the library; `fullTextAvailable(entry)` is the single derivation of `full_text` (Phase 18: `byo === true` or an `oa_url`; Phase 19 refines this one function). The outline projection (first author, 300-char abstract) is a second function in the same module. Property-tested: the output never contains a citekey or title outside its input.
- **D-18-22 — Planner context (GRND-12).** Inputs: `brief` {topic, thesis, discipline, tone, paper_type}, `section` {n, suffix, slug, title, purpose, role, depends_on, word_target, voice} from the OUTLINE row (the stub's values where the row lacks them), `upstream` (for each depends_on section with a planned PLAN.md: slug, title and its `## Claims` summarised to ≤ 600 chars), `sources` (fenced records of the section's allowed set only).
- **D-18-23 — Planner contract and PLAN.md.** `SectionPlannerSchema` = `{frontmatter: {section, slug, title, depends_on, assigned_sources}, claims: [{claim, sources[], evidence, counterexamples}] (≥1), structure: [{paragraph, purpose, claims[]}] (≥1), voice}` as native structured output. Validation: schema; section, slug and depends_on equal the OUTLINE row; `assigned_sources` ⊆ the section's allowed set (its current PLAN.md `assigned_sources`: the outline allocation plus `plan --research`/`add --remap` additions) and ⊆ LIBRARY citekeys; every claim's sources ⊆ `assigned_sources`. One corrective turn naming the problems; still invalid → EXIT_ERROR `planner output invalid: …`, nothing written, the previous PLAN.md (stub) intact. PLAN.md is rendered from the validated object: v2 frontmatter (outline entry kept, `stub` dropped, `status: planned`) and body `## Claims` (per claim: sources, evidence, counterexamples), `## Structure`, `## Word target`, `## Voice`; `parsePlanClaims` reads the body back. The router sends a `stub: true` PLAN.md to plan and a planned one to write; only write sets `writing`. `readAssignedSources` throws on a malformed PLAN.md instead of returning `[]`.
- **D-18-24 — Drafter input (FEED-02).** `DrafterInputSchema` (strict) grows to the full payload — planPath, `paper` {topic, thesis, discipline, tone}, section {n, suffix, slug, title, role, word_target}, `sources` (citekeys) and `sourceRecords` (SourceContextRecord[]) of exactly the PLAN.md `assigned_sources`, `plan` (the PLAN.md body without lifecycle keys), `voiceHint`, optional `styleProfile` text — and the request is built only from that validated object (`buildDrafterRequest(input)`), for single and wave writes alike. Voice: the section's PLAN/OUTLINE voice hint wins; else the STYLE.json render; else a tone default from the preset; the STYLE.json render is also sent as `style_profile` when style-match is on (PRD §7.18). No assigned sources: the drafter is told to write without citations and write prints a WARN naming `plan N --research` and `add`. The drafter template states the quote policy (quote directly only from sources with `full_text: true`; paraphrase the rest) for Phase 19's GRND-14 to enforce.
- **D-18-25 — Containment (FEED-04).** `bin/lib/draft-containment.ts` `checkDraft(draft, {assigned})` returns violations (`unassigned-citekey` today; Phase 19 adds `quote-without-full-text`) using the one citation grammar module. After drafting, a violation gets one corrective turn naming the keys; if it persists, DRAFT.md is not written (the rejected draft goes to `DRAFT.rejected.md`), PLAN.md gets `status: failed` and `failure_reason: citekey X not assigned to section N`, other sections are untouched, and write exits EXIT_BLOCKED. The router sends a failed section with no DRAFT.md to `status`/attention naming `pensmith write N` (never a paid loop). An injected `cite [@evil9999]` is caught the same way.
- **D-18-26 — write chains to verify (GRND-15).** `bin/cli/verify.ts` exports the verification of one section; `write N` and wave write run it after each successful draft unless `--no-verify`, print each section's verify status, and exit with verify's code (EXIT_BLOCKED on a blocking verdict). With `--no-verify` the section stays `written`.
- **D-18-27 — Wave write (GRND-16).** A malformed PLAN.md is one line naming the file and the field (zod issues formatted, never `ZodError`); independent sections still draft; the command exits non-zero. Stubs not yet planned are skipped with a note; a single `write N` on a stub refuses (EXIT_USAGE) naming `pensmith plan N`. Waves run up to `--max-parallel` (default 5) and `--max-parallel 1` prints no warning; the docs say so and a test checks the default.

### Bare runs, dry runs and the corpus (GRND-18, GRND-19)

- **D-18-28 — One bare invocation completes one step; a section's step is plan → write → verify.** `bin/pensmith.ts` gains the one chain used by bare `pensmith`, `next` and `resume`: a `plan N` decision runs plan, then (if it succeeded) `write N`, which chains verify; a `write N` decision runs write (+ verify); a `verify N` decision runs verify; any other decision runs its verb. It prints what ran and the router's next step (`next: …`), and exits with the last verb's code. Without `--yolo`, the outline and export gates prompt in a terminal and exit EXIT_APPROVAL otherwise. From a folder with only assignment.txt, repeated bare `pensmith --yolo` reaches done in at most 5 + N invocations.
- **D-18-29 — `--dry-run` runs in `./.paper-dry-run/`.** Under `--dry-run` (and `PENSMITH_DRY_RUN=1` in children) `paperDir()` is `<root>/.paper-dry-run`. It is seeded from `.paper/` when that exists (a copy through `atomicWriteFile`, with `SEED.json` holding a fingerprint of `.paper/`: relative paths, sizes and sha256), kept across dry runs, and re-seeded when the fingerprint changes. The real `.paper/` is never created, never read after seeding and never written; the session lock is the paper's. `.paper-dry-run` is treated like `.paper` wherever `.paper` is special (project-root folding, `hasPaper`, walks, the repo `.gitignore`), and a dry-run paper is never registered in the global library. Exports go to `.paper-dry-run/export/` with `.dry-run` before the extension (`DRAFT.dry-run.md`, `.docx`, `.pdf`), and done prints that path. Every dry-run artifact carries a marker — `.paper-dry-run/DRY-RUN.md`, the D-17-08 marker line in RESEARCH/VERIFICATION/COMPILE-REPORT, the same `offlineMarkerLine()` dry-run line in the INTAKE/OUTLINE/PLAN bodies (their writers add it when `networkMode().dryRun`, never under the test runner alone), `synthetic: true` on every dry-run LIBRARY entry — except the section DRAFT.md files, `.paper-dry-run/DRAFT.md`/`FINAL.md` and the exports, which stay zero-trace (they feed the export) and are disclosed by name and location. The P17 refusal of `--dry-run` over a real paper is replaced by the workspace; the refusal of a normal run on a legacy `.paper/DRY-RUN.md` paper stays. A dry run over a real paper's real citations reports them UNVERIFIABLE (dry-run) — it never fakes a verdict.
- **D-18-30 — A dry run loops.** Bare `pensmith --dry-run` (and `next`/`resume --dry-run`) repeats D-18-28 steps until the router reports done or attention, a step fails or a gate refuses, or a decision repeats without progress. With `--yolo` it goes intake → done in one invocation; without `--yolo` it stops at the first gate it cannot answer (non-TTY: exit 3 — `intake-defaults` in a fresh folder, `outline-approval` in a paper whose research is done — with nothing registered). The OFFLINE MODE banner names the workspace path.
- **D-18-31 — The recorded e2e corpus.** `tests/fixtures/e2e-corpus/MANIFEST.json` names: the assignment (`tests/fixtures/assignment.txt`, the hash-pinned PRD §15 assignment), `mock-script.json` (scripted replies for intake-clarifier and topic-disambiguator; every other slug uses the contract stubs), the cassette root `tests/fixtures/cassettes/e2e/<adapter>/` (a separate root so per-adapter refreshes never wipe it), the adapters recorded and any adapter expected to miss offline (a response over the 51200-byte cap cannot be recorded; the chain tolerates an offline miss), and the expected section count and run bound. `npm run cassettes:refresh -- --corpus e2e` records it live through the real modules: `discoverSources` with the scripted queries, then each library entry's Pass-1 lookups (Crossref work, arXiv id, retraction query). HARDEN-01 reuses the corpus.

### Review amendments (rounds 1 and 2)

- **D-18-37 — Outline and plan offer only the sources the citation verifier can check.** Pass 1 resolves a cited source only through Crossref until VRFY-11 (Phase 20), so a source with no DOI, a DataCite DOI (`10.48550` arXiv, `10.5281` Zenodo, `10.6084` figshare, `10.5061` Dryad) or a synthetic dry-run DOI outside a dry run is always FABRICATED once cited, stranding its section. `source-context.ts` `verifierBlindSpot` withholds those entries from the outline's `sources` block and from the planner's allowed set; `outline` names them in a WARN and again at the approval gate (with the fix: `add` the version-of-record DOI), `plan` names the ones allocated to the section. This amends FEED-01 and FEED-03 (REQUIREMENTS.md) and PRD §7.3/§7.5. VRFY-11 widens the predicate in the same change; outline and plan need no edit.
- **D-18-38 — STATE.json is the one authority on section identity.** A section is its registration `{n, suffix?, slug}` (hence its folder); OUTLINE.md rows must list the same sections (`section-registry.ts`). When they disagree (a user-renamed, renumbered, deleted or added row; a Tier-1 registration with no row) the router reports `status (attention)` naming the divergence and `pensmith outline`, compile refuses, and plan/write/verify resolve `<n>` from STATE.json and refuse a section whose row disagrees — never creating a second folder for a registered number. `pensmith outline` without `--force` applies an existing OUTLINE.md without a model call: a structural check (unique ids and slugs, known and acyclic `depends_on`, citekeys in LIBRARY.json — a named refusal, never a later internal error), matching by slug, a renumbered section refused (folders are never renumbered, D-18-18), a registered section the table no longer lists archived to `sections/_archive/` (in a paper with drafts only through the `reoutline` gate, which `--yolo` answers for this, the user's own edit), and stubs for new rows. A registered lettered section whose folder does not exist is created as `NN<letter>-<slug>`. The scheduler's cycle and wave-override errors are named one-line refusals (PensmithError).
- **D-18-39 — The compiled draft's currency is decided from content.** compile writes `.paper/COMPILE-INPUTS.json` (v1: the compiled sections' ids and slugs, and the sha256 of each section's DRAFT.md and VERIFICATION.md); the router recompiles only when that list or a hash differs from the paper now (a paper compiled before the record falls back to mtimes and `sections_count`). `done` writes FINAL.md whenever it is absent or older than the DRAFT.md it exported (a humanized FINAL.md of this compile is kept), so a recompile never leaves bare runs looping on `done`. The `--dry-run` seed keeps each copied file's mtime.
- **D-18-40 — Every Pandoc citation form is a citation to the fail-closed consumers.** `citation-token.ts` reads author-suppressed `[-@k]` (alone and in clusters), braced `@{k}` and narrative `@k` / `-@k` (Pandoc's rule: `@` not after a letter, digit or backslash; not in code, comments or link targets), Unicode keys included, for FEED-04 containment, Pass 1, the Pass-3 quote attribution (a quote followed by any citation, or introduced by a narrative one in the same sentence), GATE-04, the density count, revise rename, the export bibliography and compile's boundary smoother (a smoothed boundary must cite exactly the keys the original did; the D-13 placeholders mask only bare `[@k]`, so a model-added or rewritten citation of any form is rejected like a drift). The narrow `CITATION_TOKEN_RE` substitution grammar is unchanged; VRFY-09 (Phase 20) still owns the full parser (locators, prefixes, UNPARSEABLE rows, the chokepoint).
- **D-18-41 — What `--yolo` answers is written once.** Each gate in `gates.ts` carries a `summary`; `pensmith --help` generates the `--yolo` description from the registry, and `tests/gates-registry.test.ts` checks the README list against it.
