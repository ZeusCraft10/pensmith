## Why this phase exists

The 2026-09-25 audit found every source path broken or partial on the live user path: arXiv answered 301 and the transport did not follow it; Unpaywall's current schema parsed to null for every DOI and requests without an email got 422; the retracted Wakefield paper passed verify because a 200 carrying an inner error read as "not retracted" and was cached; Crossref hard-coded `retracted: false` and dropped consortium authors, journal, volume and pages; keyless OpenAlex and Semantic Scholar 429s were retried futilely (15 each) and Retraction Watch took 115 calls in one run; research kept every candidate when the evaluator rejected them all; there were no tiers, no policy, no RESEARCH.md source list, no books, no BYO folder ingest, no Zotero client; `add` hydrated the wrong work from a PDF's licence line; CITATIONS.bib broke on Cyrillic names and dropped abstracts, eprints and journals; `plan --research` always returned 0 hits; pdf-parse kept burning CPU after its timeout (gap register: AUD-12, E2E-2/6/12/15/18, NFR-4..8/11/18/19/22/23/34/45, CORE-11..16/24/32, RM-7/22/23, SC-1, UX-19, SWP-13..16/30/44/54/55/57..65/71/77/79/80/85/98/105/118/120..122/125/128/129).

Phase 17 already landed part of the foundation (D-17-47: retraction lookups through Crossref REST `works?filter=updates:<doi>`; the arXiv base URL is https; the cassette recorder; the one library writer; the pinned, size-capped transport). This phase finishes the source layer on top of it.

### Contracts

- **D-19-05 — Three-way lookups (SRC-05).** Every adapter exports `lookupById(id) → found | not-found | failed` (`sources/lookup.ts`). `not-found` is a definitive registrar answer (404, or an empty exact-id result); `failed` is everything else (non-200 after retries, 429, an exhausted or open host, transport error, timeout, a body that fails the adapter's schema check, a missing precondition such as Unpaywall's email). `fetchById` stays as `unwrapLookup(...)`: candidate, `null` for not-found, and a thrown `SourceLookupError` for failed — a failed lookup can no longer read as "no such record". Pass 1 catches `SourceLookupError` from the Crossref re-fetch and records UNVERIFIABLE with the reason (blocking, S-03; the label and the identifier-less search are VRFY-12, Phase 20). Pass 3 reports the reason as its unavailable text. `OfflineEgressError` is unchanged (a mode, not an outcome).
- **D-19-06 — Redirects (SRC-01, S-05).** `http.ts` follows redirects in its own loop: GET and HEAD only (never a POST, never an `opts.llm` request, whose redirect is an error), at most 5 hops (the 6th raises `RedirectError('too-many')`, message `too many redirects`), a revisited URL raises `loop`, `https→http` raises `downgrade` (`http→https` is allowed), a 3xx without `Location` raises `no-location`, 303 becomes GET. Each hop is a fresh request: scheme allowlist, DNS resolve and SSRF validation, a new pinned dispatcher, its own `--show-prompts` mirror line and `kind:"http"` SESSION.log record. A cross-origin hop drops `authorization`, `cookie`, `x-api-key`, `zotero-api-key` and every other `SENSITIVE_HEADERS` entry. undici's `maxRedirections` stays 0. The cache stores the final response under the original URL. There is no trusted-source-label bypass anywhere: every URL, including an Unpaywall OA link or a redirect target, is resolved and validated.
- **D-19-07 — Recorded redirects and binary bodies.** Cassettes gain `location` in the recorded header allowlist and `bodyEncoding: "base64"` for non-text bodies (PDFs), within the 51200-byte cap; offline replay follows recorded hops through the exact-match store. A small real PDF behind a real redirect (`http://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf` → 301 https, 13 KB) is the recorded redirect-to-PDF fixture; the MockAgent chain test covers 301 → 302 → 200.
- **D-19-08 — Politeness and rate limits (SRC-17).**
  - User-Agent `pensmith/<version> (mailto:<email>)` for Crossref (and its retraction lookup), OpenAlex and Unpaywall; plain `pensmith/<version>` everywhere else (PRIVACY.md unchanged in scope).
  - Token buckets are keyed **per host** (Crossref search, works and retraction lookups share `api.crossref.org`), seeded from the per-source table. `X-Rate-Limit-Limit` / `X-Rate-Limit-Interval` (e.g. `3` / `1s`) lower that host's rate and never raise it.
  - A `Retry-After` longer than the 30 s cap marks the host exhausted until that time: the request is not retried and `RateLimitExhaustedError` is thrown; later requests to that host in the process fail fast with zero sockets.
  - A per-host circuit breaker opens after 3 consecutive 429/5xx **responses** (retries count), throws `CircuitOpenError`, prints one stderr line per host, and skips the host for the rest of the run; a success resets the count; after 10 minutes an open breaker lets one probe through (so the long-lived MCP server recovers). Fixture-served answers never count.
  - Floors, documented in `docs/SOURCES.md` next to PRD §12: arXiv 1 request per 3 s; Crossref from its own headers (today 3/s polite); OpenAlex 10/s within its keyed daily budget; PubMed 3/s; Semantic Scholar 1/s; Unpaywall 10/s; Open Library 1/s; Zotero 5/s plus its `Backoff` header. PRD §12 is amended where it differs.
- **D-19-09 — One contact-email resolver (SRC-03, SRC-17).** `contact-email.ts` reads the variable named by `[network] contact_email_env` (default `PENSMITH_CONTACT_EMAIL`). A paper's config travels with the paper, so the name is honoured only if it is an upper-case identifier containing `EMAIL` or `MAILTO`, and the value only if it looks like an email; otherwise one warning and the default. http.ts, OpenAlex (`mailto`), Unpaywall (`email`), the retraction lookup (`mailto`) and the doctor probe all use it; the integration pass adds the `contact-email` chokepoint row so nothing else reads the variable.
- **D-19-10 — Keys (SRC-06).** `OPENALEX_API_KEY` (name from the global runtime.json `openalexApiKeyEnv`) is sent as `api_key`; `PENSMITH_S2_API_KEY` as `x-api-key`. HTTP cache keys are derived with secret query parameters and secret headers removed; SESSION.log shows `api_key=REDACTED` (existing); cassettes scrub them (existing), and `tests/cassette-no-leak` also scans recorded paths for secret parameters. A keyless OpenAlex 429 or exhausted host reads `keyless daily budget exhausted — set OPENALEX_API_KEY (free)`; keyed, `rate limited (retry after …)`. Semantic Scholar keyless reads `HTTP 429 — rate limited; set PENSMITH_S2_API_KEY`, and its once-per-run notice says keyless requests share a public pool that is often rejected. No OpenAlex key exists in this environment: the committed keyless recording stays, the keyed live round trip is a live-lane check that prints a visible "skipped: OPENALEX_API_KEY not set" notice, and 19-VERIFICATION lists it as an open maintainer item.
- **D-19-11 — Retractions (SRC-04).** Crossref `toCandidate` sets `retraction_status` from its own record — a `retraction` / `withdrawal` / `removal` / `partial_retraction` entry in `updated-by` updating this DOI, or a `RETRACTED:` title prefix → `retracted` with details; otherwise `clear`, because the Crossref record itself carries the Retraction Watch notices as `updated-by` (search `select` adds the field, `/works/{doi}` returns it whole). `crossCheckRetractions` keeps its signature and mutates each candidate: `retracted` / `clear` / `unknown` (with the reason), skipping candidates whose Crossref record already decided and de-duplicating DOIs; nothing is swallowed. Research prints `WARN: N retracted source(s)…` and `retraction status unknown for N source(s): …`; RESEARCH.md shows both. Pass 1's live re-query stays blocking; its verdict label becomes RETRACTED in Phase 20 (VRFY-15) — this phase's spawned-CLI test asserts the blocking verdict names the retraction and compile and done exit 4.
- **D-19-12 — Unpaywall (SRC-03).** Parse `z_authors[].raw_author_name` (current) and `family`/`given` (legacy); collect every `oa_locations[]` entry; `oa_pdf_url` = the best PDF (best_oa_location's `url_for_pdf`, then other `url_for_pdf`s, then PMC / arXiv PDF links). No contact email → `failed: Unpaywall skipped: set PENSMITH_CONTACT_EMAIL` plus a one-time stderr warning, never a silent null; a 4xx surfaces its body's message.
- **D-19-13 — Crossref completeness (SRC-05).** Authors with only `name` become corporate authors `{Name}`; editor-only works carry `editors` and use them as authors; `container-title` → venue, `volume`, `issue`, `page` → pages, `publisher`, `ISBN`, JATS-stripped abstract, and `type` mapped to CSL (journal-article → article-journal, proceedings-article → paper-conference, book/monograph/edited-book/reference-book → book, book-chapter → chapter, report → report, dissertation → thesis, posted-content → preprint, dataset → dataset). OpenAlex, arXiv (bare id, DOI, `journal_ref`, abstract, `preprint`), PubMed (PMID, PMCID, journal, volume, issue, pages) and Semantic Scholar (venue, externalIds) fill what they know.
- **D-19-14 — Books and non-DOI sources (SRC-11).** `sources/books.ts`: Open Library `search.json` (title/author search; `isbn=` lookup with `editions.*` sub-fields — one request, no redirect, edition-specific publisher and date), Google Books `volumes?q=isbn:` as the keyless fallback. `add isbn:<ISBN>` resolves through it. The `nber` preference is Crossref search with `doiPrefix: '10.3386'`. JSTOR and APA PsycNET have no free, ToS-compliant search API, and PhilPapers' documented API has no search endpoint and needs a registered key (its site also blocks automated clients); PRD §8 is amended to say their content is reached through OpenAlex / Crossref / PubMed coverage, and the adapter plan maps `jstor` → openalex + crossref, `psycnet` → pubmed + openalex, `philpapers` → openalex. `templates/presets/disciplines.json` (a seam S-A file) is not edited.

### Research

- **D-19-15 — Disambiguation and queries (SRC-08).** Contract `{ambiguous, scopes: [{label, description, queries}] (1–3)}`; the schema accepts 1–20 queries per scope and research clamps to 5–10 (first 10; fewer than 5 padded with the deterministic expansion of `query-expansion.ts`). Under `PENSMITH_NO_LLM` the stub is that expansion of the brief's topic and discipline, disclosed on stdout and in RESEARCH.md. The scope gate (`research-scope`) runs when `ambiguous` or more than one scope: TTY select; `--scope <n|text>` (1-based index, or a label/description match; no match → EXIT_USAGE listing the scopes); `--yolo` takes scope 1 and says so. `--queries <n>` caps the query count within 5–10. The up-front non-TTY refusal accounts for what `--scope` answers (the prune gate still needs a terminal or `--yolo`). Tier 1 submits the same schema through PLUG-07 (Phase 23); this phase exports the schemas and a pure `applySourceEvaluations()` for it.
- **D-19-16 — Adapter plan, tiers, policy, evaluator (SRC-07, SRC-09, SRC-10).**
  - Plan (`adapter-plan.ts`): without `[sources] allowed_databases`, the preset's preference (mapped: `books`, `nber`, `jstor`/`psycnet`/`philpapers` substitutes) followed by the rest of PRD §10's default five (openalex, semanticscholar, crossref, arxiv, pubmed); with it, exactly those databases, preference-ordered first. `zotero` joins when configured. `SOURCE_DATABASES` gains `books` and `nber`. Results rank by evaluator relevance, ties by the best preference rank among the adapters that found the work.
  - Search-side filters: `fromYear` from `[sources] min_year` where the service supports it.
  - Tier (`source-tier.ts`, pure): deterministic from metadata (Crossref/OpenAlex type and venue, arXiv-only → preprint, ISBN/book → book, report from a government publisher or `.gov` domain → gov-report), else the evaluator's tier.
  - Policy (`source-policy.ts`, pure, PRD §10 defaults): `min_year`, `allow_preprints`, `allow_books`, `allow_gov_reports`, `allow_news` (type article-newspaper / article-magazine), `peer_reviewed_only`, `require_doi`. `require_doi` means *a registrar identifier* — a DOI, or an ISBN for a book, an arXiv id for a preprint, a PMID — because the History, Literature and Philosophy presets prefer books, which have ISBNs; PRD §10 is amended with that reason. Excluded candidates are listed with their rule in RESEARCH.md.
  - Evaluator: payload `candidates` = `[{citekey, title, authors ≤5, year, venue, type, doi, tier_hint, abstract ≤500}]`, sent once, fenced; verdict `{citekey, keep, reason ≤200, relevance 0–1, tier}`; tier, relevance and the reason (`why_relevant`) persist. Explicit rejection of every candidate → `no relevant sources` with guidance, LIBRARY.json untouched, RESEARCH.md log written, exit 1 (the keep-all fallback is gone). An evaluator that fails (after the corrective retry) or omits a candidate leaves it `not evaluated`, kept with a disclosure line — never silently.
  - The `research-prune` gate lists kept candidates (preselected) and evaluator-rejected ones (deselected, hint = reason), each with tier, year and an abstract excerpt, then accepts DOIs / arXiv ids / URLs to add through the SRC-13 path (wired in the integration pass).
  - Per-adapter outcomes print as a table on stdout and in RESEARCH.md: count, or `failed (<reason with hint>)`, `offline: no recorded fixture`, `skipped (not configured)`, `skipped (not in allowed_databases)`. Zero usable sources after policy and pruning → exit 1 naming why.
- **D-19-17 — RESEARCH.md is a view plus a log (SRC-09, SRC-14, SRC-15, SRC-16, GRND-17).** The generated block (above `RESEARCH_LOG_END`) holds the run log and the sources block; the sources block (`research-md.ts`) lists every LIBRARY entry with its formatted reference, tier, relevance, tags (search, bring-your-own, zotero, added, plan-research, imported), why-relevant note, abstract excerpt, retraction and unhydrated notes. Every ingest path calls `refreshResearchSources(root)` after `upsertSources`. Notes below the end line are never touched; list items only (no `### `), so the tutorial's curated-claims parser is unaffected.
- **D-19-18 — `plan N --research` (GRND-17).** `section-research.ts`: refuse up front without a terminal and without `--yolo` (`plan-research`, exit 3, nothing touched); queries = the user's query and the query joined to the section title; the same discovery, dedup, retraction check, tiers, policy and evaluator (topic = brief topic + section title, scope = the query); with `pii_redaction` on, the query is redacted before any model or search request; hits shown for approval (known works marked "already in library as …"); `upsertSources` (`plan-research:§N`), then only that section's PLAN.md `assigned_sources` gains the real citekeys (under the plan lock; status and `verified_against_draft_hash` untouched), a `sections/<NN>-<slug>/RESEARCH-LOG.md` entry is appended, and the RESEARCH.md sources block is refreshed (curated notes preserved). ### Library, `add`, BYO, PDFs

- **D-19-19 — BibTeX round trip (SRC-12).** `person-name.ts` parses author strings: `Family, Given[, Suffix]`; `Given Family` without a comma (lower-case particles — van, van der, de, de la, von, di, da, du, del, della, le, la, ten, ter, bin, al — join the family); `{Corporate}` as one literal name; a single token (e.g. 王小明) as the family. The writer emits raw UTF-8 names (no `{\u …}` escapes), `abstract`, `journal`/`booktitle`, `volume`, `number`, `pages`, `publisher`, `editor`, `isbn`, `eprint` + `archivePrefix = {arXiv}` + `primaryClass`, and maps `type` to @article / @book / @incollection / @inproceedings / @techreport / @phdthesis / @misc; `parseBib` preserves `eprint`/`archivePrefix`. A fast-check property (≥ 1000 runs, unicode names and titles) proves writeBibtex → parseBib is lossless. When verify finds a CITATIONS.bib that does not parse and LIBRARY.json exists, it re-renders the bib from the library (the library writer's `rerenderCitations`) with one notice, then verifies.
- **D-19-20 — `add` identifies the right work or refuses (SRC-13, SRC-14).** `source-input.ts` classifies input: DOI (including `DOI: 10.…` and `%2F`-encoded doi.org URLs, via doi.ts), arXiv (`arXiv:`, bare new-style and old-style ids such as `hep-th/9901001v2`, `math.GT/0309136`, upper-case archives, trailing period; `arxiv.org/abs|pdf` URLs — an arXiv URL is an identifier, its PDF is not downloaded), PMID (`PMID:`/`pmid:`), ISBN (`isbn:` or a checksum-valid 10/13-digit string), URL, local PDF, directory. PDFs go through `pdf-identify.ts`: embedded Info/XMP identifiers, then a DOI or arXiv id in the first pages, then a title (a layout heuristic that skips licence, permission, arXiv-stamp, affiliation and email lines) and first author; Crossref + OpenAlex title search accepts a hit only when title Jaro-Winkler ≥ `TITLE_JW_THRESHOLD` **and** first-author family ≥ `AUTHOR_JW_THRESHOLD`. A single `add <file.pdf>` that is not confidently identified exits 1 with `could not confidently identify this PDF — pass its DOI: pensmith add <doi> --pdf <file>` and changes nothing; `add <doi> --pdf <file>` attaches the PDF as the work's BYO copy. `add` refreshes RESEARCH.md; the remap gate (`add-remap`) offers a multi-select preselecting only sections whose title, purpose or claims overlap the source (`section-relevance.ts`); `--remap <key> --section N` changes only §N; `--remap <key>` alone remaps the relevant sections it prints. `add <url>` goes through the transport like everything else (offline = exact fixture or a named refusal; the old blanket offline refusal goes); an SSRF refusal prints its reason and exits 1.
- **D-19-21 — Bring-your-own PDFs (SRC-15).** `byo-ingest.ts` serves `new --pdfs <dir>` (also recorded as `[sources] byo_pdf_dir`), `add <dir>`, and research (which ingests new files in `byo_pdf_dir` first — integration). Per PDF: size cap, sha256, extraction in the worker, identification as D-19-20 (only a title or an identifier leaves the machine: one lookup request per PDF, asserted), and on no confident match the source is kept with local metadata, `hydrated: false`, and a warning — never as a search hit. The PDF is stored at `.paper/sources/<citekey>.pdf` and LIBRARY.json records `{file, sha256, text_sha256}` and provenance `byo` (tag bring-your-own); re-ingest is idempotent by sha256; a search hit with the same identifier merges into the BYO entry. `byo-text.ts` `byoText(root, entry)` is the only way to read BYO text: it re-hashes the PDF (mismatch → unavailable, "PDF changed since ingest"), serves text from a cache in the data dir keyed by the PDF hash only when its hash equals `text_sha256`, else re-extracts and checks; a loose `.paper/sources/<citekey>.txt` is never read (S-17). Pass 2/3 and the compile recomputation consume it in Phase 20 (VRFY-19). Optional GROBID header extraction runs when `PENSMITH_GROBID_URL` names a loopback server (environment only, so a paper file cannot point it anywhere).
- **D-19-22 — The PDF worker (SEC-02).** `pdf-worker.ts` runs pdf-parse (and its transient-FormatError retry) in a `worker_threads` worker: `.ts` entry with the tsx loader from source, `.js` from `dist/` (the plugin bundle layout is PLUG-02's). One-shot settled guard over message / error / exit / timeout; on timeout the parent awaits `worker.terminate()`; worker stdout/stderr are captured, so pdf-parse's console noise never reaches the user. API: `extractPdf(buf) → {text, numpages, info, xmp, imageOnly}`; `extractPdfText` keeps its contract. PyMuPDF runs when pdf-parse throws or returns near-empty text; the script imports `pymupdf` (falling back to `fitz` on old releases) and writes the text to a result file, so interpreter warnings on stdout/stderr are never text; image-only → `imageOnly: true` (`add` refuses it, BYO keeps it unhydrated). pdf-parse stays confined to `pdf-text.ts` and `pdf-worker.ts` (the ESLint exemption names both). SECURITY.md row 9 becomes PROVEN.
- **D-19-23 — Drafter quote policy (GRND-14).** `full-text.ts` `fullTextAvailable(entry)` = a BYO PDF with a recorded `text_sha256`, an OA PDF location (`oa_url`), an arXiv id, or a PMCID; `quotesWithoutFullText(draft, fullTextByCitekey)` lists direct quotes attributed to sources without full text. Phase 18's `source-context.ts` `fullTextAvailable` delegates to it and Phase 18's `draft-containment.ts` gains the `quote-without-full-text` violation (write's single corrective turn enforces it) at merge; Phase 18's rewritten `section-drafter.md` already carries the policy, so no template is re-pinned here. The end-to-end GRND-14 acceptance (captured drafter request flags; one corrective retry) runs in the post-merge integration.
