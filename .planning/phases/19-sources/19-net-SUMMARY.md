## Deviations and choices (with the decision they refine)

- D-19-24 doctor mapping: PASS = the CLI can read Zotero (authenticated key, reachable local API, readable public group); a detected MCP server without either is a WARN ("not authenticated for the CLI"); offline without a fixture is SKIP. The probe's detail is one line (`MCP server: …; Checked: …; Web API: …`) because the renderer indents only one line.
- D-19-24: `ZOTERO_GROUP_ID` without a key reads a public group (no key sent); the local API wins when both it and a key are set (nothing leaves the machine). Zotero library candidates carry no `last_verified` (a Zotero record is not a registrar verification). `search(query)` is Zotero's quick search per query; `pullZoteroIntoLibrary(root)` pulls the whole configured collection — the integration pass chooses which the research plan calls.
- D-19-08: model requests (`opts.llm`) keep their bucket but are outside the exhausted marker and the breaker (anthropic.ts classifies provider errors, RUN-09); `_resetBucketsForTest` resets the whole host state so other streams' tests that call it start clean.
- D-19-06: the contact email stays with the polite origin — a redirect hop to another origin gets the plain User-Agent.
- D-19-21/24: the local services are refused in sources-offline mode unless a fixture answers (only a configured loopback model endpoint is exempt, as CLAUDE.md states); a binary POST body is mirrored as its byte count.
- D-19-10: cache keys also drop the contact parameters; `SCRUBBED_QUERY_PARAMS` gains `apikey`, `token`, `access_token`.
