**Branch:** `v1/p19-adapters` (from the plan commit `2e584b7`; first two commits apply seam S-A and seam S-B byte-identically) · **Requirements:** SRC-02, SRC-03, SRC-04, SRC-05, SRC-06, SRC-11 · **Decisions:** D-19-05, D-19-09..14, D-19-25, D-19-26

## What was built

Every registrar adapter answers through the three-way lookup contract (`bin/lib/sources/lookup.ts`, seam S-B): `lookupById(id) → found | not-found | failed`, `fetchById = unwrapLookup(…)` (a failed lookup throws `SourceLookupError`, never reads as "no such record"). One shared module, `bin/lib/sources/registrar-response.ts` (new), classifies each exchange: `ok` (a 200 that passed the adapter's shape check), `status` (another HTTP status the adapter interprets: 404 = not-found, another 4xx = failed with the service's own message), `failed` (429/5xx after retries, `RateLimitExhaustedError`, `CircuitOpenError`, redirect / SSRF refusals, transport errors, a 200 that is not the service's answer). The same shape check is handed to the transport as `FetchOptions.validate`, so an error body is never cached or recorded (SRC-17); it runs again on fixture-served answers, so a synthetic error body replays as a failure. `OfflineEgressError` is rethrown untouched (a mode, not an outcome). Each adapter still calls `httpFetch(…, { maxBytes: MAX_JSON_RESPONSE_BYTES })` itself (SEC-03 test unchanged).

**Pass 1** (`bin/lib/verify/pass1.ts`): `SourceLookupError` from the Crossref re-fetch → UNVERIFIABLE `Crossref re-fetch of <doi> failed: <reason> — re-run verify once the lookup answers` (blocking); the Crossref record's own retraction → MIS-CITED `cited work is retracted (Crossref record, Retraction Watch notice at verify time): <notice>` before the live re-query; DOI comparisons (redirect check, retraction DOI de-dup) are case-insensitive; citation-js surname particles (`non-dropping-particle`) and literal (corporate) names are kept, braces are ignored in the surname comparison — so `van der Maaten` and the ENCODE consortium verify OK.
**Pass 3** (`pass3.ts`): Unpaywall `lookupById` reasons (`Unpaywall skipped: set PENSMITH_CONTACT_EMAIL — …`, failed lookups, not-found) instead of "No OA PDF available"; the OA PDF is fetched with `source: 'generic'` (no contact email, plain User-Agent), checked with `checkPdfResponse` on `bodyBytes` (`not a PDF (got text/html)`, `HTTP 404`), refusals reported (`OA PDF fetch failed: SSRF guard: …`), extraction errors caught (`OA PDF text extraction failed: …`).
**Freshness** (`freshness.ts`): a host-unavailable error on either probe is an `unavailable` row naming why, never "ok".

**Recorder** (`scripts/refresh-cassettes.mjs`): the D-19-26 query sets; per-FILE outcomes (a failed call keeps that file's committed copy and is reported; files no longer in a query set are removed); a single record that only fits without indentation (Crossref `/works/{doi}` — no `select` on that route) is written with that response on one line; every email address a response carries is redacted (Unpaywall affiliation strings held authors' addresses); `lookupById` calls record only answered lookups; arXiv calls pause 3.5 s.

**Live lane** (`scripts/live-sources.mjs`, `npm run live:sources`): 17 checks + visible SKIP lines for absent keys; fresh data dir; exit 1 on any FAIL.

## Deviations and decisions

- **`registrar-response.ts`** (new, not in the owned-path list): the shared classifier; no other stream touches it. Its `__setRegistrarSendForTest` seam (test contexts only) simulates the transport's host-availability refusals, which the base transport cannot yet produce (stream `net` lands them).
- **Pass 1 retraction from the Crossref record** (D-19-11 consequence): a record that says retracted blocks before the Retraction Watch re-query (fail closed, one request fewer).
- **Pass 1 particles / corporate names**: without them the SRC-12 acceptance ("`10.1016/j.foreco.2013.06.030` then `verify` gives Pass-1 OK") fails on `van der Maaten` (author JW 0.46), and a braced consortium would be `claimed metadata incomplete`.
- **Offline retraction status**: an offline miss in `crossCheckRetractions` is `unknown` (the reason says offline), never left `clear`/`unchecked` silently.
- **Unowned files touched because SRC-06 changed their truth**: `bin/lib/doctor/probes/runtime-config-presence.ts` no longer marks OPENALEX_API_KEY "not used yet"; `references/doctor-output.md` sentence updated and re-pinned in `tests/repo-files.test.ts`; README's `OPENALEX_API_KEY` / `PENSMITH_S2_API_KEY` rows; PRIVACY.md's services list (Open Library / Google Books, the two keys, Crossref-served Retraction Watch data); CONTRIBUTING's recorder paragraph (project contact address, per-file outcomes, email redaction, compact rendering, `npm run live:sources`); `workflows/verify.md` Pass 1 / Pass 3 steps.
