## Decisions

### Protocol

- **D-21-01 — Two streams, no seam patch.** Stream `export` (the export engine, zero trace, built-in writers, citation rendering, the export bibliography, outline-only mode) and stream `pipeline` (compile, done orchestration, the humanizer, honesty, plagiarism, flags and aliases, config v4) start from the plan commit in separate worktrees with disjoint owned paths (21-PLAN §5). The cross-stream contracts are small and additive (21-PLAN §3.3): each stream keeps every exported signature the other calls backward compatible (new optional fields only) and codes against the base signatures; the integration pass (21-PLAN §7) wires the two halves together. A stream that finds it needs a file the other owns stops and reports instead of editing it, except for the localized hunks 21-PLAN §6 lists.

### Rendering and export (stream `export`)

- **D-21-02 — Which writer makes which format.** `md` is always the built-in renderer (never pandoc: the output must not depend on what is installed, and pandoc's Markdown writer emits `:::` divs and escapes). `docx`, `pdf` and `latex` use pandoc when it is on PATH (`pdf` also needs a PDF engine: pdflatex, xelatex, lualatex or tectonic, first found), otherwise the built-in writer. A requested format is never replaced by another; stdout names the writer (`built-in docx writer — pandoc not found`, `built-in PDF writer — pandoc found but no PDF engine`). Only a format that truly cannot be produced exits non-zero (EXIT_ERROR) with one line naming why. PRD §7.9's "else markdown for docx" and §11's Pandoc bullet are amended (EXP-09).
- **D-21-03 — One citeproc pass over the whole document.** `citations.ts` (the citation-js chokepoint) gains a document renderer: one citeproc-js engine processes every citation cluster in document order (`processCitationCluster` with `noteIndex` for note styles), then makes the bibliography from the same engine. Numbering, first/subsequent/ibid note forms, disambiguation (`2020a`/`2020b`) and bibliography order are therefore the engine's, as in pandoc, and never assembled per citation. It returns rich text (a small run tree: italic, bold, superscript, subscript, small caps, link) per cluster and per bibliography entry, plus whether each cluster is a note; each writer serialises the runs (Markdown `*…*` / `^…^` / `[^n]`, WordprocessingML runs and `footnotes.xml`, PDF styled runs, LaTeX `\emph` / `\textsuperscript` / `\footnote`). The per-citation `renderCitationItems` path is retired from the exporter (kept exported for callers).
- **D-21-04 — Pandoc's citation behaviours, replicated.** The built-in path does what pandoc's citeproc does, checked against pandoc: a note citation becomes a footnote placed after following punctuation (`claim.[^1]`); a superscript style (AMA) or a note marker drops the space before it (`claim^1^.`); a suffix pandoc reads as a locator is one offline too — one that starts with a number is a page locator (`[@k 33]` → `p. 33`, carry-over 3), one that starts with a locator term keeps its label, and the pandoc differential decides the edge cases (roman numerals, ranges, a trailing comment); the reference list follows a heading — `References`, or `Bibliography` for a note style — on both paths (pandoc gets `reference-section-title`), one paragraph per entry. The locator rule lives in `citation-token.ts` (`splitLocator`, the one grammar) and a pandoc differential checks it.
- **D-21-05 — Golden files from pandoc.** `scripts/make-citation-goldens.mjs` renders one committed fixture (citing B, A, B, `[A; C]`, a `p.` locator, a bare-number locator and a narrative citation, over a bib with an article, a book and a chapter) through pandoc 3.9 citeproc for each of the 8 styles into `tests/fixtures/citation-goldens/<style>.md`, once, with the case-protected input of D-21-06. The test renders the same fixture with the built-in renderer and compares after one documented normalisation (Markdown markup, fenced divs and spans, link syntax, escapes, quote and dash spellings, whitespace). Every in-text citation string, every number, every note's placement and text, the bibliography's order, labels and entry text must be equal. A genuine engine difference in bibliography entry text (never in-text) may be recorded only as a named exception in `tests/fixtures/citation-goldens/EXCEPTIONS.json` with the CSL rule and both outputs; an in-text difference is a bug to fix.
- **D-21-06 — Case protection (carry-over 1, "china").** Neither renderer may lowercase a word the source capitalised unless it can tell the word is not a proper noun. The renderer input (the CSL items for citeproc-js and the temporary bib given to pandoc — never `.paper/CITATIONS.bib` or `export/CITATIONS.bib`, which keep the gated bytes) protects: acronyms and mixed-case words always; in a title that is not Title Case (it has a lowercase content word), every capitalised word after the first; a Title Case title is kept as written whole, because a proper noun cannot be told from a capitalised word there — no sentence-casing is better than wrong lowercasing. Both paths then print the same title.
- **D-21-07 — A local CSL file.** `--style` and `[project] citation_style` also accept a path to a `.csl` file (relative to the project root, or absolute). It is accepted only when it is well-formed XML with the CSL 1.0 namespace, a `<style>` root with `class` `in-text` or `note`, and `<citation>` and `<bibliography>` elements; a dependent style (`<link rel="independent-parent">`) is refused (rendering it would need its parent fetched). The validator is in `bin/lib/export-style.ts` (stream `pipeline`); citations.ts registers a file style under a content-hash template name, and pandoc gets a copy as `style.csl` (D-21-09). The `[project] citation_style` schema accepts the path form (config v4, D-21-26). *(Amended in review rounds 2 and 3: a `.csl` file config.toml names is used only once the user approved it for the paper — the `csl-style` gate, `style-approvals.ts` — and it is not stat'ed, read, validated or hashed before an approval for its path exists; a network path (`\\host\…`, `//host/…`) in config.toml is EXIT_USAGE outright.)*
- **D-21-08 — The zero-trace scanner.** `bin/lib/export/zero-trace.ts` scans every file an export writes — the document (docx: every XML part including core, app, custom, document, settings, footnotes, endnotes and every `.rels`; pdf: Info, XMP, every decompressed stream; tex; md) and the exported bib and RIS. *Metadata* (docx docProps and rels, PDF Info and XMP, a tex preamble, a bib/RIS field other than the entry text) must hold no absolute path, no `$HOME`, no OS username as a path segment or field value, no `.paper`, `citation-styles`, `.csl` or `.bib` path, no `.claude/plugins`, no offline or dry-run marker and no `pensmith`; docx `Application`/`AppVersion` and PDF `Producer`/`Creator` must be empty or a generic value naming neither pensmith nor the writing library; PDF `/PTEX.*` keys and other engine banners are flagged. *Author content* (the document body, notes, the rendered references) is checked only for path patterns (absolute paths, home or username path segments, the markers, a generator comment) — never for a bare word, because a paper may say "user" or "pensmith" (audit #18). *Media* (`word/media/*`, PDF image XObjects) are flagged for EXIF, XMP and PNG `tEXt`/`iTXt`/`zTXt` chunks (BRDTH-02 strips them on embed; Phase 25). `exportDraft` runs it after writing and after every scrub; on any hit, or when a scrub throws after pandoc wrote a file, it deletes every file it wrote in that call and throws `ZeroTraceError` (a `PensmithError`, EXIT_ERROR) naming the file and the finding. There is no markdown fallback after a failed scrub.
- **D-21-09 — Pandoc runs blind.** Pandoc runs with a fresh temp dir as its cwd and only relative, neutral names in argv: `input.md`, `references.bib`, `style.csl`, `out.<ext>`; the output is copied into `export/` and then scrubbed. `zeroTracePatch` keeps removing `docProps/custom.xml` with its relationship and override; `zeroTracePdf` also deletes `/PTEX.*` and other non-standard Info keys. The `--from markdown-yaml_metadata_block-raw_attribute-raw_tex` reader stays (VRFY-10 defence in depth). LaTeX and PDF put the paper title in `\title` (`--shift-heading-level-by=-1`); docx keeps it as Heading 1 (D-21-13). *(Amended in the Phase 21 reviews: the bibliography pandoc reads is `references.json` (CSL JSON, the case-protected items of D-21-06), not `references.bib`; pandoc also runs with `--sandbox` and a Lua filter that prints every image as text (review round 1) — `export/pandoc.ts`, done.md.)*
- **D-21-10 — The built-in writers.** A subset Markdown reader (`bin/lib/export/markdown.ts`) reads what a gated draft holds: ATX headings, paragraphs, emphasis and strong, inline code and code blocks, block quotes, ordered and unordered (nested) lists, links, horizontal rules, simple pipe tables and the footnotes the renderer adds. Anything else is written as its literal text with a one-line note, never dropped. A pandoc AST differential (`pandoc -t json`, 1000 generated drafts when pandoc is present; required with `CI=true`, like HARDEN-03) proves the block and inline structure agrees. The **docx writer** (jszip) uses Word's built-in style IDs (Normal, Heading1–3, Quote, FootnoteText, FootnoteReference, Bibliography with a hanging indent), real footnotes, superscript runs, blank core and app properties without `Application`/`AppVersion`, no custom.xml, no footer, epoch timestamps. The **PDF writer** (pdf-lib with `@pdf-lib/fontkit` and an OFL serif family shipped in `plugin/templates/fonts/` with its licence, subset on embed) lays out headings, paragraphs with line breaking, emphasis, block quotes, lists, page footnotes (a note that does not fit continues at the foot of the next page) and the reference list, with empty Producer/Creator and no XMP. The **LaTeX writer** emits a standalone `article` document that loads only packages every TeX distribution ships (`inputenc`/`fontenc`, `textcomp`, `hyperref`), escapes every special character, writes notes as `\footnote`, superscripts as `\textsuperscript` and the references as an unnumbered section of hanging paragraphs, and compiles under both pdfLaTeX and XeTeX (tectonic); pandoc LaTeX is `--standalone`, so its template defines the citeproc macros. The product never needs a TeX engine.
- **D-21-11 — The export bibliography.** The export holds exactly the cited keys: `export/CITATIONS.bib` is filtered from the exact bib bytes the gate judged (as now), and `export/CITATIONS.ris` is rendered from the same parsed entries (not filtered from `.paper/CITATIONS.ris`), so the key sets are equal by construction and asserted. A text with citations whose cited bibliography comes out empty is EXIT_ERROR, nothing exported. No `.paper/DRAFT.bib` is written (EXP-01's "e.g."): the cited-only file is derived at export from the gated bytes, which is the property EXP-01 asks for. The RIS writer stops wrapping tag values, splits `SP`/`EP`, writes `JO` for a journal article's container and keeps `AU  - Family, Given`; an independent parser re-imports it in a test.
- **D-21-12 — Nothing the exporter adds can carry an unverified citation (carry-over 4).** The exporter adds only: the rendered form of each citation the gate read (in-text text or a footnote whose text is the engine's note for that cluster), the bibliography of exactly the gated cited keys, the reference-section heading and the writers' layout. An invariant inside `exportDraft` asserts that the rendered key set equals the gated text's cited key set, and a property test asserts that the export's text with the rendered citations, notes and bibliography removed equals the gated text with its citation tokens removed. Footnotes are therefore produced after the gate but carry nothing the gate did not judge. Documented in the exporter header, `done.md` and PRD §7.9.

### Compile (stream `pipeline`)

- **D-21-13 — The compiled paper has a title and headings (EXP-05).** compile writes `# <paper title>` (OUTLINE.md's H1, else the brief's title) and `## <section title>` before each section in outline order; the drafter still emits no leading `#`. compile runs the text scanners over the headings it adds and refuses a title or heading they flag (naming the fix: retitle it in OUTLINE.md and run `pensmith outline`). `COMPILE-INPUTS.json` v3 records `headings_sha256` (title and section titles in order; migration `v2_to_v3`), so a retitled outline routes to compile; a v2 record (compiled before headings existed) counts as stale, so every older paper is recompiled once.
- **D-21-14 — One rewrite guard for the smoother and the humanizer.** `bin/lib/rewrite-guard.ts` masks every citation cluster (`{{cite_K_M}}`, as compile does now) and every direct quote Pass 3 would check (`{{quote_K_M}}`) before a model sees the text, and validates a rewrite: the placeholder multiset is unchanged, headings are byte-identical, nothing outside the allowed paragraphs changed, and `boundaryAdditions` finds no new text finding, quote or bare identifier. compile's smoother, done's humanizer and the Tier-1 submission tools (PLUG-07, PLUG-10) all call it. Tier 2 wires `smoothBoundary` through `complete()` with `buildPromptRequest('smoother', …)`: N−1 calls, the cost cap checked before each (`complete()`), only the last paragraph of section N and the first of N+1. A rejected boundary keeps the raw text and the report says why. Smoothing is skipped, with the reason in the report, by `--no-smooth`, `--raw`, `[compile] smooth_transitions = false`, `PENSMITH_NO_LLM` (`skipped (no LLM)`), `--dry-run` (`skipped (dry-run)`) and a sources-offline run whose model endpoint is not loopback (`skipped (offline)`). `sections/*` are never written. *(Amended in review rounds 1–3: `citationAnchorProblem` also rejects a citation moved onto another claim, moved off its own claim that still survives in another sentence (onto a sentence the model invented, a one-word sentence, or a clause after a semicolon — semicolons split claims), and a claim negated under its citation (contrastive `not only`, `rather than` excluded); done then re-judges, with Pass 2, every citing sentence the humanizer changed (`rewritten-claims.ts`) and lists the UNSUPPORTED ones at the confirmation and in VERIFICATION.md.)*
- **D-21-15 — D-12 amendment: the `claim-consistency` slug (EXP-11, S-06).** One new hash-pinned prompt, `plugin/templates/prompts/claim-consistency.md`, `inputs: [pairs]` (fenced: the sentences come from drafts), structured output `{ pairs: [{ id, verdict: CONTRADICTS | CONSISTENT | UNCLEAR, rationale }] }`, judgment tier (claude-haiku-4-5), UNCLEAR-biased ("CONTRADICTS only when both sentences cannot be true together"). Candidates are cross-section pairs of claim sentences (each section's PLAN.md `## Claims` plus the draft's claim sentences, by Pass 4's marker lexicon) ranked by shared content terms; the top `[compile] contradiction_pairs` (default 20, RUN-26) go to one call. A deterministic negation / quantifier-polarity heuristic over pairs sharing a subject and predicate runs always and is the offline floor. `Contradictions flagged: N (target 0)` counts the model's CONTRADICTS plus heuristic flags the model did not judge; a heuristic pair the model judged CONSISTENT is listed as cleared, with its rationale. Tier 1 (PLUG-07) uses the same candidate builder and schema through `bin/lib/claim-consistency.ts`.
- **D-21-16 — Density names its source (EXP-12).** The band is the discipline preset's per-paragraph band, overridden by `[verification] citation_density_min/max`, and `--discipline` overrides both. COMPILE-REPORT states the discipline and where it came from (`computer-science (from INTAKE.md)` / `config.toml` / `--discipline` / `preset default`), the band and its source.
- **D-21-17 — COMPILE-REPORT is fully populated (EXP-13).** `Transitions Changed` lists each boundary with its status, reason and before/after text; `Advisory Findings` lists each section's Pass-2 rows that are not SUPPORTED and its Pass-4 orphans, read from the section VERIFICATION.md (the Pass-2 table reader moves from `done.ts` to `bin/lib`, fail-safe as now) — a section whose Pass 2 was not run on its current draft says so; a new 8th section `## Contradictions` (D-14 additive, after the two Phase-20 sections) holds `Contradictions flagged: N (target 0)`, each pair with both sections and both sentences, the cleared pairs and the skip reason. Every skipped step names its mode: `skipped (dry-run)`, `skipped (no LLM)`, `skipped (offline)`, `skipped (--no-smooth)`, `skipped (config)`. The frontmatter `title` carries the paper title (COMPILE-REPORT is never exported). The `Phase 5 will populate` marker is deleted.

### Done (stream `pipeline`)

- **D-21-18 — The Tier-2 humanizer (EXP-14).** `bin/lib/humanizer.ts`. The skill is `<home>/.claude/skills/humanizer/SKILL.md` through a new `paths.ts` helper; under a test context it is found only when that home lies inside `os.tmpdir()` (the CI-09 rule), so no test ever reads the developer's real skill. Its body (frontmatter stripped) is the system prompt, sent as `cache_control` like every system prompt. The model call uses a new **model slug** `humanizer` in `llm-models.ts` (verb `done`, generation tier) that has no template — S-06 forbids a `templates/prompts` slug; template-coverage tests exclude it by name with that reason. The user message is the hash-pinned contract `plugin/references/humanizer-contract.md` (keep every placeholder, every heading and every quoted passage; add no citation, claim or quote; output only the rewritten text), `preserve_voice`, and the fenced, masked section text. The compiled draft is humanized one `##` section at a time; the title and headings never reach the model. `humanizeDraft()` returns text and never writes FINAL.md. `acceptHumanized()` — the rewrite guard (D-21-14), the cited-key diff (`citedKeySetChange`) and the gate core over the humanized bytes (`recomputeExportGate`) — is the one acceptance function both tiers call (PLUG-10). A rejection makes done exit EXIT_BLOCKED with every reason, write no export and leave FINAL.md untouched; `--raw` is named as the way out. A provider failure reports `humanizer failed: <reason>` and done exports the compiled draft (FINAL.md = DRAFT.md); a cost-cap refusal propagates (exit 5). Skips: skill missing (`humanizer skill not found at ~/.claude/skills/humanizer/SKILL.md — skipping`), `[humanizer] enabled = false`, `--raw` (`skipped (--raw)`), `PENSMITH_NO_LLM`, `--dry-run`, offline non-loopback. The `no Task transport` banner and the `__setTaskRunnerForTest` seam are removed (the seam's deletion from `exporter.ts` is an integration step, 21-PLAN §7). *(Amended in review round 3: the skill is found where Claude Code installs skills — `<config>/skills/humanizer/SKILL.md` with `<config>` = `$CLAUDE_CONFIG_DIR` else `~/.claude`, then the account-synced `<config>/skills/synced/<bucket>/humanizer/SKILL.md`, then an installed plugin's `skills/humanizer/SKILL.md` — `paths.ts` `humanizerSkillPath`, shared by done, the estimator, status, doctor and the capabilities resource; done prints the file it uses. `acceptHumanized` also refuses a rewrite that adds text the zero-trace author rule refuses.)*
- **D-21-19 — FINAL.md and DONE-RECORD (EXP-15, carry-over 6).** done writes FINAL.md once per successful run, after the export and the paper-level VERIFICATION.md: the accepted humanized text, else the compiled draft. Because FINAL.md is never replaced before the export, the "put the previous FINAL.md back" path is removed (a refused, declined, failed or capped done leaves FINAL.md byte-identical — tests assert the bytes, not the old message). `writeDoneRecord` keeps its signature and is called with the same hashes, so `finalMdState` and the router's done/attention decisions are unchanged. `done --only humanize` writes FINAL.md and the record after GATE-04 without exporting: FINAL.md is the finished paper (PRD §7.9) and an export is a rendering of it. *(Amended in the Phase 21 reviews: DONE-RECORD is v4 — `exported` (false after `pensmith humanize`, which the router reports as attention naming `pensmith export`; v3, review round 1) and `previous_final_sha256` (the record is written BEFORE FINAL.md and names the text it replaces, so a stop between the two leaves `stale`, never `edited`; v4, review round 2), with migrations `v2_to_v3.ts` / `v3_to_v4.ts`. The router's done/attention decisions gained: an unexported FINAL.md, a DONE-RECORD a newer pensmith wrote, `FINAL.rejected.md` (a rejected humanization of the current compiled draft, review round 2) and `EXPORT.refused.md` (done's zero-trace refusal of the current compiled draft before any paid step, review round 3) — `done-record.ts`, `router.ts`.)*
- **D-21-20 — Honesty: real or clearly absent (EXP-16, EXP-17).** The score is taken before and after the humanizer and printed and written to `.paper/VERIFICATION.md` as `<n>% AI-generated (<backend>, <ISO time>)`. Absent scores give one exact reason: `skipped (no <KEY> set)`, `skipped (no consent recorded — run pensmith done interactively once, or set honesty_consent = true)`, `skipped (consent declined in config.toml)`, `skipped (--no-score)`, `skipped (config: honesty_score = false)`, `unavailable (offline)` / `(dry-run)`, `unavailable (<backend> rejected the API key)`, `unavailable (rate limited)`, `unavailable (network: …)`; the after line adds `N/A (humanize skipped with --raw)`, `N/A (humanizer not installed)`, `N/A (humanizer failed: …)`, `N/A (humanizer disabled)`. Consent is `[humanizer] honesty_consent` in config.toml (config v4): asked once in a terminal through the `detector-consent` gate (label made backend-neutral; the disclosure line before it names the backend and its host), the answer — yes or no — persisted through `config.ts`; `--yolo` never grants it; without a terminal and without recorded consent nothing is sent. Every scoring run prints the disclosure line before sending. The framing and every backend's disclosure are read verbatim from the hash-pinned `references/honesty-framing.md` (new Originality and Sapling disclosure sections; transparency-only; re-pinned). *(Amended in the Phase 21 review, round 1 — as REQUIREMENTS.md EXP-17 records: consent is NOT stored in config.toml. It is recorded per paper (the project root's real path) and per detector in the pensmith data dir (`detector-consent.json`, `bin/lib/detector-consent.ts`), because config.toml travels with a shared or copied paper and a paper file must never consent for its next reader. `[humanizer] honesty_consent` stays a config v4 key only as an opt-out: `false` never sends; `true` GRANTS NOTHING. The no-consent reason is `skipped (no consent recorded — run pensmith score (or pensmith done) once in a terminal and answer the detector question)` (honesty.ts `NO_CONSENT_REASON`). Review round 3: an error answer names the service's own short reason — `unavailable (Originality.ai: Enterprise Subscription Required … (HTTP 422))` — honesty.ts `serviceReason`.)*
- **D-21-21 — Originality and Sapling (EXP-18).** Two adapters behind the existing `HonestyBackend` interface, through `http.ts`, with `ORIGINALITY_API_KEY` / `SAPLING_API_KEY`, each with its own size cap and the shared consent gate and budget gate. The stream confirms the current request shape and score field from each vendor's documentation and records the source in the module header. A key never reaches a log, the `--show-prompts` mirror or a cassette: header authentication where the API offers it, else the key is registered as a secret before the request. - **D-21-22 — Plagiarism (EXP-19, EXP-20).** Phrases are 6–10-word windows of body paragraphs (never the title, headings, citation tokens, quoted passages, block quotes, list items or the reference list), ranked by rarity against a shipped English word-frequency list (`plugin/templates/wordfreq/`, licence compatible with redistribution in an AGPL-3.0 project, attribution in the file and in README credits), at least one per paragraph in paper order, up to `[verification] plagiarism_max_phrases` (config v4, default 30). Each is sent as a quoted DuckDuckGo HTML query through `http.ts` (its rate limits unchanged).
