# Phase 20: Verifier Completeness (VERIFY) — Context and decisions

**Milestone:** v1.0.0 Open Source Release · **Base:** `c8f28e3` on `akhil/pensive-faraday-qx3o58` (Phases 17, 18 and 19 merged) · **Plan:** [20-PLAN.md](20-PLAN.md) · **Seam:** [seams/20-seam-S-C.patch](seams/)
**Requirements (22):** VRFY-09 … VRFY-29, HARDEN-03 · **Carry-overs assigned here:** (1) the freshness table's `DOI HEAD | ok` for a source with no DOI or missing from the bib; (2) research marking a non-Crossref DOI's `retraction_status` `clear` without asking who registered it; (3) PubMed entries without abstracts (Pass 2 has no text); (4) Pass 1 for the remaining DataCite DOIs and a metadata search for identifier-less entries.

## Why this phase exists

The 2026-09-25 audit (gap register AUD-2, AUD-14, AUD-20, AUD-THEME-B, CORE-16/25/29/31..37, E2E-6/9/12/13/18, NFR-4/7/18/22/23/28/34/45/46/50, RM-4/10/11/22, SC-2, UX-12/16, SWP-16/20/58/63..65/77..85/91/99/110/111/120/123..126) found the non-negotiable "the verifier blocks compile and export" holding only for the forms and sources the verifier happened to see. Phases 17–19 closed a lot of it: the broad Pandoc reader (D-18-40/42), the three-way registrar lookups (D-19-05), Pass 1 at arXiv / PubMed / the books registries and the DataCite arXiv DOI (19-VERIFICATION §5–§9), `doi-ra.ts`, `full-text.ts`, `byo-text.ts` and the PDF worker. What is left, re-checked on the base commit:

- **Forms the gates cannot see.** A citation-shaped token that does not parse (`[@]`, `[@k`, `@{k`, `[@k [see note]]`) is silently absent; author-date prose, footnotes, a reference list, `\cite{}` and `<cite>` carry fabricated attributions straight through verify, compile and done (V4/V6/V7). `pass2.ts:81`, `pass4.ts:104`, `llm-text-stubs.ts:195` and `citation-density.ts:147` still hold private `\[@` regexes.
- **Legitimate sources that cannot pass.** Zenodo / figshare / Dryad and every non-Crossref, non-arXiv DOI are UNVERIFIABLE at best; an entry with no identifier is FABRICATED without a search; PubMed "Family INITIALS", particles, U+2010 hyphens, subtitles, editor-only works and online-first years still produce false MIS-CITED rows; a DOI whose Crossref record answers under another DOI passes on a strict title/author match alone, and nothing checks the year.
- **Pass 3 cannot fail on a real paper.** Offline it never looks; live it reports every missing text as a non-blocking `PDF_UNAVAILABLE`, so an unchecked quote compiles; ten-word / sixty-character floors skip short fabricated quotes; there is no cache, so compile and done cannot recompute it.
- **compile and done trust files.** compile reads VERIFICATION.md rows and re-verifies only stale sections; done lists section folders, trusts their rows and diffs keys on FINAL.md only when a humanizer ran. A hand-written VERIFICATION.md, a hand edit to `.paper/DRAFT.md`, a key outside the section's sources or a placeholder draft all export.
- **Advisory passes judge the wrong text.** Pass 2 reads a bib `abstract` (none for PubMed), one sentence per key, sequentially; Pass 4 needs two weak markers and a citation anywhere within 500 characters, so it misses "Social media use clearly causes depression in every adolescent."
- **`last_verified` is never written** and nothing re-checks old citations; the freshness table invents `ok` rows.

## Decisions

### Seam and protocol

- **D-20-01 — One seam, S-C, applied first by every stream.** `seams/20-seam-S-C.patch` was built on `c8f28e3` and verified green (`seams/README.md`). It adds `bin/lib/verify/verdicts.ts` — the verdict vocabulary (D-20-02), the blocking sets, the one section-status rule `sectionOutcome`, `blocksCompile`, `quoteTextSha256` / `quoteId`, the `TextFinding` type and the two Pass-2 table headers — and routes the existing readers through it: `verify.ts`'s aggregation, `verdict-rows.ts` `BLOCKING_VERDICTS` / `blockingRowReason`, `compile.ts` `productionReVerify`, `done.ts` GATE-04 and its Pass-2 table reader (4- or 5-column), and the router's retry-online one-liner. It declares the cross-stream contract fields: `Pass1Options.bibEntries` (implemented) and `.refresh`, `Pass1Result.checkedAt`, and on `Pass3Result` `id`, `quoteSha256` and `localFile` (implemented). With base verdict labels every reader behaves exactly as before; a label a stream adds is blocking or passing on every branch from its first commit, so no stream can pass a new failing label through a reader it does not own. No stream edits a seam file or hunk; a seam defect stops the stream and the orchestrator issues one corrective patch every stream applies identically.
- **D-20-02 — The verdict vocabulary.** Pass 1 rows: `OK`, `OK-BYO`, `FABRICATED`, `MIS-CITED`, `RETRACTED`, `UNASSIGNED`, `UNPARSEABLE`, `UNSUPPORTED-FORM`, `UNRESOLVABLE`, `UNVERIFIABLE-NETWORK`, `UNVERIFIABLE`. Pass 3 rows: `PASS`, `FUZZY`, `NOT_FOUND`, `UNVERIFIABLE-QUOTE`, `UNVERIFIABLE-NETWORK`, `UNATTRIBUTED`. Draft rows: `PLACEHOLDER`, `NO-CITATIONS`. Passing: `OK`, `OK-BYO`, `PASS`, `FUZZY` (and the pre-Phase-20 Pass-3 `OK`). Failing (Status `failed`): every other Pass-1 label except the two UNVERIFIABLEs, `NOT_FOUND`, `UNATTRIBUTED`, `NO-CITATIONS`. Unverifiable (Status `unverifiable`, blocking): `UNVERIFIABLE-NETWORK`, `UNVERIFIABLE`, `UNVERIFIABLE-QUOTE` (unless accepted, D-20-22), `PLACEHOLDER`. An unknown label fails (fail closed). `PDF_UNAVAILABLE` / `TEXT_UNAVAILABLE` are read only from files an older pensmith wrote (advisory, as before); nothing writes them after Phase 20. PRD §7.7's PASS / NOT_FOUND / FUZZY_MATCH become PASS / FUZZY / NOT_FOUND plus the two new outcomes (amended, D-20-31).
- **D-20-03 — "No answer" versus "an answer with no text".** A lookup or fetch that got no usable answer — an offline fixture miss, a transport error, a timeout, DNS failure, HTTP 429 or 5xx after retries, an exhausted host, an open circuit breaker, a cache miss while the network is down — is `UNVERIFIABLE-NETWORK`: blocking, "retry verification when online", never FABRICATED, never replaced by fixture replay, never acceptable (VRFY-12, D-V1-03). A definitive answer that holds no checkable text — no open-access location, paywalled (abstract only), no contact email for Unpaywall, an OA link that answered 403/404, not a PDF, a corrupt or image-only PDF — is `UNVERIFIABLE-QUOTE` with that reason: blocking, and the only verdict a per-quote acceptance can cover (S-04).
- **D-20-04 — Local files can add refusals, never remove them (S-17 extended).** compile and done read VERIFICATION.md, PLAN.md, QUOTE-ACCEPTANCES.json, BYO text, LIBRARY alternates and COMPILE-INPUTS.json as inputs to check. A local record may only make the gate stricter: `Status: failed`, a PLAN.md write failure, a missing Status line, a missing VERIFICATION.md or a stale hash refuses; no local record turns a recomputed blocking verdict into a pass. The only local file that can lift a recomputed verdict is QUOTE-ACCEPTANCES.json, and only for a quote whose recomputed verdict is `UNVERIFIABLE-QUOTE` in the same draft (D-20-22).
- **D-20-05 — One gate core, three callers.** `bin/lib/verify/gate.ts` (stream `gate`) computes every blocking row for one text: the text findings (UNPARSEABLE, UNSUPPORTED-FORM — stream `grammar`'s scanners), Pass 1 over cited keys and bare identifiers (stream `registrar`), UNASSIGNED against an allowed-key set, the draft checks (PLACEHOLDER, NO-CITATIONS), Pass 3 (stream `quotes`) and the acceptance lift. verify runs it per section and writes VERIFICATION.md; compile runs it per section over the exact draft it concatenates; done runs it over the exact bytes it exports. Nothing else decides whether a citation passes.

### Grammar and forms (stream `grammar`)

- **D-20-06 — `citation-token.ts` is the only citation parser, enforced.** `citationItems` returns key, prefix, suffix, locator, locator label, suppress-author and narrative for every Pandoc form (the locator table moves from `exporter.ts` into `citation-token.ts`; the exporter imports it). The four private regexes go. New chokepoint row `citation-grammar` (VRFY-09): a regular-expression literal, or a `new RegExp(…)` / `RegExp(…)` whose pattern argument, contains `\[@` or `@\{`, anywhere in `bin/**`, `mcp/**`, `hooks/**` except `bin/lib/citation-token.ts`. `scripts/eslint-rules/chokepoint.mjs` gains the matcher kind `regex-literal` (pattern tested against `node.regex.pattern`) and `tests/chokepoints.test.ts`' harness re-checks it; failing fixture `tests/fixtures/chokepoints/citation-grammar.violation.ts.txt`; the CLAUDE.md chokepoint row becomes a real row. The committed `plugin/` bundles are outside the scope (their sources are linted).
- **D-20-07 — UNPARSEABLE.** `findUnparseableCitations(md): TextFinding[]` reports, with its line: a `[@` / `[-@` not followed by a key (`[@]`, `[@ k]`), an opening bracket whose `@key` run has no closing bracket in its paragraph (`[@k`), `@{` with no balanced closing brace before whitespace, and a bracketed run that holds a citation-start `@key` together with a nested bracket (`[@k [see note]]`). An `@` Pandoc cannot read as a citation start (`name@host`, `\@k`) is not reported. The rules are checked against pandoc 3.9 by the extended `tests/citation-grammar-pandoc.test.ts`; where Pandoc renders a citation the grammar does not model, the grammar reports it (fail closed).
- **D-20-08 — UNSUPPORTED-FORM.** `bin/lib/verify/unsupported-forms.ts` `findUnsupportedForms(md): TextFinding[]` reports: parenthetical author-date (`(Nguyen & Patel, 2019)`, `(Smith et al., 2019, p. 4)`, `(Smith 2020; Lee 2021)`, `(World Health Organization, 2020)`), narrative author-date with `et al.` or two names (`Nguyen and Patel (2019)`, `Smith et al. (2019)`) — a lone `Name (1919)` is not flagged ("the Treaty of Versailles (1919)"); Markdown footnote references and definitions (`[^x]`, `[^x]: …`) and inline notes (`^[…]`); a heading or a bold/emphasised line naming a reference list (References, Reference List, Bibliography, Works Cited, Literature Cited, Notes, Endnotes, Sources) and every entry under it up to the next heading; raw TeX citation commands (`\cite`, `\citep`, `\citet`, `\parencite`, `\textcite`, `\footcite`, `\autocite`, `\nocite`, starred and bracketed-option forms); HTML `<cite>` and `<sup>` reference markers. Spans the grammar proves are code (`citation-token.ts` codeSpans, D-18-42) are skipped; everything else is scanned (fail closed). Section drafts, the compiled DRAFT.md and FINAL.md are all scanned (gate core). Notes the exporter generates for note styles are produced after the gate and never re-enter it.
- **D-20-09 — HARDEN-03's oracle.** `tests/citation-integrity.property.test.ts` generates drafts with fast-check (numRuns ≥ 1000) and batches them into a few pandoc calls (one `Div` per draft, split from `pandoc -t json`) so the run stays under a minute. Property A (every Pandoc `Cite` key is in the Pass-1 key set or the draft has a blocking text finding), Property B (every key the offline exporter renders is in the Pass-1 set), Property C (an unsupported or unparseable form never yields `verified`; a key absent from the bib is FABRICATED and blocks — checked through the gate core at integration). Fixed regression example `Claim A [@smith2020 [see note]].` When pandoc is missing the test fails if `CI=true` and otherwise skips with one loud stderr line. `ci.yml` installs pandoc 3.x on all three runners (a small hunk; Phase 23a may edit `ci.yml` for CI-05).

### Registrars (stream `registrar`)

- **D-20-10 — Pass 1 asks every identifier at its own registrar.** A DOI: Crossref (case-insensitive after `normalizeDoi`); on Crossref's definitive 404, doi.org's agency of the prefix (`doi-ra.ts`): DataCite → `api.datacite.org/dois/<doi>` (new adapter `sources/datacite.ts`, three-way lookup, `HttpSource` `datacite`); another agency that answers content negotiation (mEDRA, JaLC, KISTI, …) → `https://doi.org/<doi>` with `Accept: application/vnd.citationstyles.csl+json`; Crossref's own prefix or no agency → FABRICATED; any agency whose record cannot be fetched → the entry's arXiv id / PMID / ISBN, else `UNVERIFIABLE` naming the agency (never FABRICATED). The DataCite arXiv DOI keeps its arXiv route. A DOI-less entry keeps the arXiv → PubMed → books route. An entry with no identifier gets a metadata search (D-20-11). A Crossref edited volume or other editor-only work compares its first editor. `pass1-identifiers.ts` widens with it, so `verifierBlindSpot` offers Zenodo / figshare / Dryad sources again (D-18-37).
- **D-20-11 — The match.** Before Jaro-Winkler: NFKD with combining marks removed, every Unicode dash and hyphen (U+2010–U+2015, U+2212) to `-`, particles and compound surnames compared both with and without the particle (the higher score counts), PubMed "Family INITIALS" read as family `Family`, "et al." and trailing initials dropped, a braced corporate name compared whole, non-Latin names compared in their own script (no transliteration of either side). The title is compared whole and without its subtitle (after the first `:`, ` - `, ` — ` or `. `), plain text (markup.ts), and the better score counts. The year: when both the entry and the record carry one, it must be within ±1 (online-first versus issue year); a larger gap is MIS-CITED. MIS-CITED rows name the failing field (`title`, `first author`, `year`). A metadata search for an identifier-less entry (Crossref `query.bibliographic` with title + first author + year; the books registries' title search for a book) passes only a strict match (title ≥ 0.95 JW with or without subtitle, first author ≥ AUTHOR_JW_THRESHOLD, year ±1) → `OK` naming the matched identifier; a definitive empty or non-matching answer from every applicable search → `UNRESOLVABLE`; a failed search → `UNVERIFIABLE-NETWORK`.
- **D-20-12 — Aliases and bring-your-own only on real evidence (VRFY-14).** A Crossref answer carrying another DOI than the one claimed passes only when the registrar asserts the relation at verification time: the claimed DOI's Crossref `relation` names the returned DOI as `is-identical-to`, `is-version-of`, `has-version`, `is-preprint-of` or `has-preprint`, or doi.org's handle for the claimed DOI redirects (HEAD, not followed) to the returned DOI — and the title / author / year match still holds. `alternate_dois` in LIBRARY.json are never read as evidence. `OK-BYO` applies only to an entry with no registrar identifier, or whose registrar lookup ended `UNVERIFIABLE-NETWORK`, and whose PDF `byo-text.ts` re-hashes to its recorded sha256 (not `asserted`); the row names `sources/<file>` and the first 12 hex digits of the hash. A definitive not-found stays FABRICATED whatever local text exists. `runPass1Unit` is removed; every test drives `runPass1`.
- **D-20-13 — RETRACTED, and "unknown" is never "clear" (VRFY-15, carry-over 2).** A retraction is the blocking `RETRACTED` row (was MIS-CITED + `retraction: true`), echoed on stderr as `pensmith verify: RETRACTED — <key>: <notice>` and named at compile and done. Retraction data exists for Crossref-registered DOIs (Crossref's `updated-by` and the Retraction Watch feed) and PubMed ("Retracted Publication"); for a DOI another agency registered the row is `OK` with `retraction status unknown (no retraction data for <agency> DOIs)` in its reason and in the summary — reported, never shown as clean, not blocking. A retraction lookup that failed stays `UNVERIFIABLE-NETWORK` (blocking). Research's `crossCheckRetractions` sets `clear` only for a DOI Crossref registered (the candidate came from Crossref, or doi.org's agency lookup of its prefix says Crossref — one lookup per prefix per run); any other DOI is `unknown` with that reason. The freshness pass re-checks every `unknown` status on each verify and done (never from cache).
- **D-20-14 — Bare identifiers (VRFY-10).** `doi.ts` `findBareIdentifiers(md)` (building on `findDoisInText` / `findArxivIdsInText`) finds `doi:10.…`, `https://doi.org/…`, `arXiv:…`, arxiv.org abs/pdf URLs, `PMID: …` and pubmed.ncbi.nlm.nih.gov URLs outside provable code; `runPass1` verifies each at its registrar and writes one row keyed `doi:<doi>` / `arXiv:<id>` / `PMID:<id>`: found → `OK` naming the record's title (there is no claimed metadata to compare); definitive not-found → FABRICATED; no answer → UNVERIFIABLE-NETWORK. An identifier inside a reference list is covered by that list's UNSUPPORTED-FORM rows.
- **D-20-15 — `last_verified` (VRFY-28, carry-over 1).** `LIBRARY.json` `last_verified` is the time of the latest registrar answer that gave the citation a passing Pass-1 verdict (a live fetch: now; a cached answer: its `savedAt`, which the adapters now put in the candidate's `last_verified` instead of "now"). verify and done pass `refresh` = the cited keys whose `last_verified` is null or older than `[verification] recheck_after_days` (default 30): their lookups skip the HTTP-cache read and write the fresh answer back (`FetchOptions.refresh`). Pass 1 returns `checkedAt`; the gate records it through `library.ts` `recordLastVerified` (under the library lock; a wave verify loses nothing). compile only reads. The library writer renders `last_verified = {<ISO>}` into `.paper/CITATIONS.bib`; `exportCitedCitations` writes only standard fields to `export/CITATIONS.bib` (an allowlist; `last_verified`, `note = {RETRACTED}` and every other non-standard field are stripped — zero trace). The freshness table: a DOI source gets its DOI HEAD row; a source with no DOI says `no DOI — checked at <registrar> by Pass 1`; a key missing from the bib says `not in CITATIONS.bib — see its Pass-1 row`; never an `ok` for a probe that was not sent.
- **D-20-16 — PubMed abstracts (carry-over 3).** The PubMed adapter fetches abstracts with `efetch.fcgi?db=pubmed&rettype=abstract&retmode=xml` for the ids esummary returned (one request per ≤ 200 ids) and records `abstract` (and `pmcid` from the article ids); an efetch failure leaves the abstracts empty and is named in the adapter's status line, never failing the search. The recorded e2e corpus is re-recorded (`npm run cassettes:refresh -- --corpus e2e`, D-18-31) because the adapter's requests change.

### Quotes (stream `quotes`)

- **D-20-17 — The quote extractor (VRFY-18).** `extractQuotes` returns every direct quote in document order with `id` (`q1`, `q2`, … — `verdicts.ts` `quoteId`), its line, its locator and one entry per cited key: inline quotes of at least `[verification] quote_min_words` words (default 5; config schema v3 with the version-only migration `v2_to_v3`, S-20) in straight or typographic double quotes, typographic single quotes, block quotes (one quote per `>` run), a citation right after the quote (any form, clusters checked against each key, locators kept), a citation right before it in the same sentence (`[@k] writes, "…"`, `@k notes that "…"`), or a narrative citation introducing it. Excluded by rule: fewer words than the minimum (scare quotes), a quoted title (preceded by `titled` / `entitled` / `called` / `named` / `the article` / `the book` / `the paper`, or Title Case with no sentence-ending punctuation inside and at most 12 words), quotes inside provable code. A direct quote with no attributable citation is one row keyed `(unattributed)` with verdict `UNATTRIBUTED` (blocking). `full-text.ts` `quotesWithoutFullText` (GRND-14) reads the same extractor.
- **D-20-18 — Where Pass 3 finds text, and the cache (VRFY-19).** Order: the user's own PDF through `byo-text.ts` (re-hashed; local, zero network), then every Unpaywall `oa_locations[].url_for_pdf` (best first, de-duplicated), then the Europe PMC open-access full text of the work's PMCID (`https://www.ebi.ac.uk/europepmc/webservices/rest/PMC<id>/fullTextXML`, new adapter `sources/europepmc.ts`, `HttpSource` `europepmc`), then the arXiv PDF of its arXiv id. Every fetch goes through `http.ts` with redirects followed; PDFs are decoded from `bodyBytes` and extracted in the SEC-02 worker with every error caught (an unhandled rejection is a test failure). Extracted text is cached in `pensmithDataDir()/source-text/<sha256(url)>.json` (`{url, final_url, content_sha256, text_sha256, text, saved_at}`, text capped at 4 MiB), written only after a successful extraction, keyed by URL and checked against the content sha256, with the TTL of the source that fetched it (`http.ts` exports its TTL table); like the HTTP cache it is never read or written when sources are offline, where recorded fixtures replay the Unpaywall, PDF and Europe PMC answers exactly and a miss is `UNVERIFIABLE-NETWORK`. A second verify, compile or done on an unchanged paper therefore makes no PDF request. A quote found verbatim (after normalization) is `PASS`, above `QUOTE_LEV_THRESHOLD` otherwise `FUZZY`, below it `NOT_FOUND`; D-20-03 decides the two UNVERIFIABLE outcomes and their reasons (`no open-access copy`, `Unpaywall needs a contact email — set PENSMITH_CONTACT_EMAIL`, `paywalled (abstract only)`, `fetch failed: …`, `image-only PDF`). A quote checked against the user's PDF reads `verified against your local file <name>` and sets `localFile`. `full-text.ts` (the drafter's quotable flag) never marks a source Pass 3 cannot check; it may mark fewer (a PMCID is quotable only when the library recorded an open-access check).
- **D-20-19 — The quote acceptance tests run the production path (VRFY-29).** `runPass3Unit` is removed. `known-bad-quotes.json` rows are drafts: each quote is found by `extractQuotes` and checked by `runPass3` against local text served as the source (a hash-verified BYO PDF built from the fixture text, or a recorded OA fixture); every PDF artifact class (ligature, soft hyphen, smart quotes, ellipsis variant, diacritic) appears in the source text and in the claimed quote, with one genuine quote per class that must PASS; the fixture's hash is re-pinned in `tests/repo-files.test.ts`.

### The gate (stream `gate`)

- **D-20-20 — verify's flow and file.** verify sets PLAN.md `status: verifying` and removes `verified_against_draft_hash` before any pass runs (a crash never leaves an earlier `verified`), and always ends in `verified`, `failed` or `unverifiable`. Every early return persists a status: a missing DRAFT.md → `writing` (the router re-drafts; VERIFICATION.md says so); a missing or empty CITATIONS.bib with cited keys → FABRICATED rows, `failed`, EXIT_BLOCKED. CITATIONS.bib is parsed entry by entry (`citations.ts` `parseBibEntries`: every `@type{key, …}` block parsed on its own, returning the entries that parse and the keys / lines that do not); with a LIBRARY.json the existing re-render runs first (SRC-12); a cited key whose entry does not parse is `UNPARSEABLE` naming the key and line; the entries that parse go to `runPass1` through `bibEntries`; no parse error reaches the user as a stack. VERIFICATION.md: the offline marker (when offline), `# VERIFICATION (Section N, slug)`, `Status: …`, `Draft: sha256 <computeDraftHash>`, then `## Summary` — a table `| Pass | Verdict | Count |` listing every Pass-1, Pass-3 and draft label with a non-zero count plus the Pass-2 verdict counts, the Pass-4 orphan total and the freshness warning / unknown counts — then `## Pass-1`, `## Pass-3`, `## Draft checks`, `## Accepted quotes` (when any), the freshness table, `## Pass-2`, `## Pass-4`. Row formats: Pass 1 `- <key>: **VERDICT** — titleJW=…, authorJW=… — reason` (a text finding's key slot is `L<line>`); Pass 3 `- <key> [q<N>] ("<snippet>…"): **VERDICT** — lev=… — reason`; draft rows `- draft: **VERDICT** — reason`. `parseVerdictRows(renderVerdictRows(keys))` round-trips every key `CITEKEY_GRAMMAR` accepts (property test) and a summary parser proves the counts equal the rows.
- **D-20-21 — Membership and placeholder checks (VRFY-17, VRFY-24).** `UNASSIGNED`: a cited key not in the section's PLAN.md `assigned_sources` (at done: not in the union of the compiled sections' `assigned_sources`), with the remedy `pensmith plan N --revise` or `pensmith add <id> --remap`; it is its own row next to the key's registrar row. `NO-CITATIONS`: a draft citing nothing while `assigned_sources` is non-empty → `no citations; N sources assigned` (an introduction with no assigned sources and no citations verifies). `PLACEHOLDER`: `write` prefixes a draft produced in LLM-stubbed mode (`PENSMITH_NO_LLM=1` or `--dry-run`) with the one-line marker `<!-- stub draft (no model configured) — not real prose -->` (the RUN-21 mock LLM serves the stub text without it, so mock-driven chains are real drafts to the gate); outside `--dry-run` a draft carrying it is `PLACEHOLDER` (unverifiable, blocking — S-13 lets other sections go on and compile refuses naming `pensmith write N` with a model configured); under `--dry-run` it passes, and compile removes the marker lines from the compiled dry-run draft so no dry-run export carries it. Tests that drove `PENSMITH_NO_LLM` writes into verify / compile / done expecting success move to the mock LLM, `--dry-run`, `--no-verify` or seeded drafts (named in the stream summary).
- **D-20-22 — Per-quote acceptance (VRFY-20).** Record: `sections/<NN>-<slug>/QUOTE-ACCEPTANCES.json`, `{ "$schemaVersion": 1, "acceptances": [{ "quote_id", "citekey", "quote_sha256", "excerpt" (≤ 80 chars), "draft_sha256" (computeDraftHash of the draft and its assigned sources), "accepted_at", "via": "flag" | "prompt" }] }`, schema `bin/lib/schemas/quote-acceptances.ts`, read and written only by `bin/lib/quote-acceptance.ts`, written only by verify (the CLI; the Tier-1 verify tool of PLUG-10 calls the same function after an AskUserQuestion confirmation). `pensmith verify N --accept-quote <id>` (repeatable) records the named quotes after the passes ran, only for ids whose row is `UNVERIFIABLE-QUOTE` (any other id: exit 2 naming its verdict, nothing recorded); an interactive run with such rows asks the registry gate `quote-accept` (a multi-select of the quotes plus "accept all" — the only way to accept several at once); `--yolo` never answers it; without a terminal it is skipped (the section stays unverifiable, exit 4). An acceptance lifts a row only when the gate's recomputation yields `UNVERIFIABLE-QUOTE` for the same citekey and `quote_sha256` and the section's current draft hash equals `draft_sha256`; at done the exported text's quote is matched to the acceptances of the compiled sections whose current draft hash still matches. A hand-written acceptance line in VERIFICATION.md means nothing. Accepted quotes are listed with their timestamps in VERIFICATION.md, COMPILE-REPORT.md (new `## Accepted Quotes` and `## Quotes Verified Against Your Files` sections, D-14 additive) and done's confirmation.

### Advisory passes (stream `grammar`)

- **D-20-28 — Pass 2 on real source text (VRFY-21, VRFY-22).** Every (citing sentence, key) pair is judged once — sentences split by the Pass-4 splitter, keys read with `citationItems` so `[@smith2020, p. 5]` yields `smith2020` — with at most 5 requests in flight (`budget.ts` Semaphore). - **D-20-29 — Pass 4's floor and the per-paragraph audit (VRFY-23).** Deterministic: a sentence (≥ 8 words, not a question, not a definition) is a claim when it has one strong marker — a causal verb (`cause(s|d)`, `lead(s) to`, `result(s|ed) in`, `increase(s|d)`, `decrease(s|d)`, `reduce(s|d)`, `improve(s|d)`, `lower(s|ed)`, `raise(s|d)`, `drive(s)`, `prevent(s|ed)`), a universal quantifier (`every`, `all`, `always`, `never`, `no one`, `none`), an evidential verb in any inflection (`show/shows/showed/shown`, `demonstrate(s|d)`, `find/finds/found`, `report(s|ed)`, `indicate(s|d)`, `prove(s|d|n)`, `reveal(s|ed)`, `confirm(s|ed)`, `establish(es|ed)`), a statistic or percentage (`73%`, `40 percent`, `per cent`, `N times`, `twice as`), a comparative change (`more|less|higher|lower|greater|fewer than`, `rose`, `fell`, `doubled`, `tripled`) — or two weak markers (the R6 list). It is an orphan when the sentence itself carries no citation of any Pandoc form. The LLM (the `orphan-label` slug, rewritten: input `paragraph`; output `{ "claims": [{ "sentence", "needs_citation", "supported_by": [keys] }] }`) runs once per paragraph with a claim or an ambiguous sentence and can only add orphans (a sentence it marks `needs_citation` with no `supported_by` key that the paragraph really cites, and that carries no citation); the deterministic count is a floor. `renderPass4Section` lists per paragraph the counts and each orphan sentence (clamped, table-safe). Pass 4 stays advisory.
