## Deviations and choices

- D-20-11 / VRFY-13 self-consistency: the live lane found two false blocks the unit table did not cover, both fixed here: a compound surname split differently by two databases ("Reid Chassiakos, Yolanda (Linda)" at Crossref vs "Chassiakos, Yolanda Reid" from OpenAlex's display name) — `name-match.ts` also compares each word of a compound surname; and Semantic Scholar's merged record pairing the 2023 journal DOI of Ghai et al. with the 2021 preprint year — research now confirms each kept aggregator DOI at Crossref (`registrar-confirm.ts`; same request Pass 1 makes, so the answer is cached for verify; best-effort, never fatal, nothing under `--dry-run`).
- `DATACITE_DOI_PREFIXES` keeps its three prefixes (documentation of the well-known DataCite repositories) but no longer makes anything uncheckable; an identifier-less entry stays withheld from the outline (`NO_IDENTIFIER_REASON`) even though Pass 1 can now search for it — a search that finds no strict match blocks, so offering it would strand sections.
- D-20-16: the efetch answer keeps the 8 MiB structured-response cap (SEC-03's `tests/response-size-cap.test.ts` requires `MAX_JSON_RESPONSE_BYTES` on every adapter call); research asks at most its search limit per query, far below it, and an over-cap answer is a named failure like any other.
- The stderr RETRACTED warning is written by `runPass1` itself (so every caller — verify, write's chained verify, compile / done re-checks — shows it); the gate should not print a second one.
- `OfflineEgressError` from a DataCite / content-negotiation / metadata-search lookup is a no-answer (UNVERIFIABLE-NETWORK), like Crossref's.

## Hand-offs

1. **gate:** `runPass1(draftMd, bibPath, { root?, bibEntries?, refresh? })` — `refresh` is a `ReadonlySet<string>` of citekeys whose cache read is skipped (the entries older than `recheck_after_days`); every row a registrar answered has `checkedAt` (ISO) for `recordLastVerified(root, stamps)`. `runFreshnessForDraft(draftMd, bibPath, { bibEntries?, root? })` returns `FreshnessResult[]` (`warnings`, `skipped`, `ok`, `info`, `recheck`); with `root` it re-checks and records unknown retraction statuses itself. Row wording: RETRACTED `cited work is retracted (<registrar> at verify time: <notice>)` / `(Retraction Watch, re-queried at verify time: …)` / `(recorded when the source entered the library…)`; UNVERIFIABLE-NETWORK ends `— re-run verify once the lookup answers`, or starts `offline: no recorded fixture — re-run online` / `dry-run: no live re-fetch under --dry-run — re-run online` (`UNVERIFIABLE_OFFLINE_REASON`, `UNVERIFIABLE_DRY_RUN_REASON`, `RETRY_ONLINE` exported). `retractionWarningLine(row)` is exported if the gate wants the same stderr text elsewhere.
2. **grammar (or integration):** `source-context.ts` `excludedRemedy` still says "(for a Zenodo / figshare / Dryad record, the DOI of its published version)"; no withheld reason can be a DataCite DOI any more. `workflows/plan.md`, `workflows/outline.md` and `skills/plan-section.md` list "only a Zenodo / figshare / Dryad DataCite DOI" among the withheld sources — for the 23a merge / integration docs sweep.
3. **integration:** `add` of a DataCite / mEDRA / JaLC DOI still refuses ("this version adds DOIs registered with Crossref only", `source-input.ts`, not owned here); it can now resolve through `sources/datacite.ts` / `sources/doi-cn.ts` the way Pass 1 does.
4. **integration (D-20-16):** the recorded e2e corpus was **not** re-recorded here — it still replays (an unrecorded efetch is named, never fatal; `e2e-corpus-manifest` and every e2e-chain suite pass). Re-record once after all four streams merge (`npm run cassettes:refresh -- --corpus e2e`), so one corpus reflects every stream's request changes; the recorder now keeps doi.org GETs and 404 / redirect hops and drops an over-cap efetch from a search.
5. **README (integration §7):** the verdict list (RETRACTED, UNRESOLVABLE, UNVERIFIABLE-NETWORK, OK-BYO), DataCite / content negotiation, `last_verified` in `.paper/` only, `npm run live:verify`.
6. **Rate buckets (`http.ts`, SRC-17):** `tests/http-rate-limit.test.ts` "Crossref declaring 3 / 1s …" failed in two full-suite runs and in 1 of 8 parallel isolated runs while the other streams' suites loaded the machine: grants spaced exactly one interval apart leave no room for the grant-to-arrival time varying between requests. Tokens now refill 5% under the nominal rate (`GRANT_MARGIN`; docs/SOURCES.md says so) — 0 failures in 32 parallel runs afterwards, and every http / sources suite passes. The live lanes spend OpenAlex's keyless daily budget — run them with `OPENALEX_API_KEY` set or expect OpenAlex to be reported exhausted on a second run the same day.
