Pensmith guides you through a paper-writing workflow: **intake → research → outline → (plan → write → verify, for each section) → compile → done**. It ships as a [Claude Code](https://claude.com/claude-code) plugin and as a Node.js command-line tool; both run the same `pensmith` CLI.

What makes it different from asking a model to write your paper: a section cannot be compiled or exported while it carries a citation the verifier flagged as `FABRICATED` or `MIS-CITED`, a citation of a retracted work (`RETRACTED`) you have not acknowledged, a citation it could not check because no registry answered or the entry has no identifier to look up (`UNRESOLVED`), a citation it cannot check at all because it was typed as text (`RAW_CITATION`) or does not parse (`UNPARSEABLE`), or a quote it marked `NOT_FOUND`. That check is deterministic, runs per section, and is not skippable.

## Status

**0.3.0-alpha.1 is an alpha**, the first release of a rebuild. Expect rough edges, and read what it does today:

- **Drafting needs an API key.** Intake questions, outlines, section plans and drafts are generated by the pensmith CLI's own calls to Anthropic, in the plugin as well as on the command line. Set `ANTHROPIC_API_KEY` before you start Claude Code or run `pensmith`. (Generating inside your Claude Code session instead is planned.)
- **The humanizer is not run.** `pensmith done` reports the AI-likelihood score when you enable it, but it does not call the humanizer skill yet.
- **The plugin is a thin layer.** It adds one skill, one session-start hook and the `pensmith` command. There is no MCP server.

## How it works

```mermaid
flowchart LR
    A[intake] --> B[research]
    B --> C[outline]
    C --> D{per section}
    D --> P[plan]
    P --> W[write]
    W --> V[verify]
    V -->|pass| D
    V -->|"blocking verdict"| X[blocked: revise and re-verify]
    X --> P
    D -->|all sections verified| E[compile]
    E --> F[done / export]
```

- **A paper is a project; a section is a phase.** Each section gets its own `.paper/sections/<N>-<slug>/` folder holding its `PLAN.md`, `DRAFT.md` and `VERIFICATION.md`. Re-doing section 3 never touches sections 1, 2, 4 or 5, and the verifier runs on one section at a time.
- **Intake keeps the assignment and your answers.** `pensmith new` reads the assignment from `--from <file>`, or from an `assignment.txt`, `.md` or `.pdf` in the folder, and keeps it word for word in `.paper/PROJECT.md`. It then asks six questions (topic, discipline, length, citation style, audience, counterargument), with suggestions from the assignment, and stores your answers in `.paper/INTAKE.json`, which research, the outline and the export read. Without a terminal it prints the questions as one JSON line and exits 3; answer them with `pensmith new --answers '<json>'` (or a JSON file). The citation style you choose is saved as `[project] citation_style` in `.paper/config.toml`.
- **The outline is the one list of sections.** `pensmith outline` asks the model for the outline as structured JSON and checks it before you see it: unique slugs, dependencies that exist and form no loop, a counterargument section when the intake says one is needed (`--no-counter` waives it), assigned sources that are in `.paper/LIBRARY.json`, and no citation in any heading. It writes `.paper/OUTLINE.json`, renders `OUTLINE.md` from it, and creates each section's folder with a stub `PLAN.md` (`status: stub`). Every step that walks the sections reads that list. If you edit `OUTLINE.md`, `pensmith outline` checks the edit and takes it in; until then pensmith goes back to the outline step rather than use a list you changed. A section folder the outline no longer names is reported and left alone.
- **A plan is checked too.** `pensmith plan N` gets the section's sources, claims and brief from the model as structured JSON, checks that every source is in the library, and writes `PLAN.md` itself: the frontmatter comes from the outline, with `status: planned`. A section that already has a plan is not planned again unless you pass `--force`. In a `pensmith write` of the whole paper, a `PLAN.md` that cannot be read fails only its own section.
- **A draft is never replaced unasked.** `pensmith write` drafts only sections whose plan is `planned` (or `writing`, a draft that did not finish). A section already drafted, verified or edited by hand is left as it is and named, and `pensmith write N` refuses it (exit 2); `--force` drafts it again and keeps the old draft as `DRAFT.md.bak`. A section with only a stub plan is not drafted until `pensmith plan N` has planned it.
- **Everything for a paper lives in `.paper/`**, settings (`config.toml`) and state (`STATE.json`) included, never in the folder around it. A paper started with pensmith 0.2 or earlier, which kept those two files in the project folder itself, is moved into `.paper/` the first time pensmith runs there; a `config.toml` that also holds settings of another tool is left as it is, and only pensmith's tables are copied. `.paper/.gitignore` keeps the unredacted intake (`INTAKE.raw.local`) and the added PDF texts (`sources/`) out of git.
- **Section writers see only their own sources.** Research builds a library; the outline assigns sources to sections; each section is drafted from the sources its `PLAN.md` assigns. The drafter is shown those works from `.paper/LIBRARY.json` (title, authors, year, venue, abstract) and no others, marked as data rather than instructions, and the outline author and the planner see the library the same way. A draft that cites any other key, cites none of its own sources, or writes a citation as text, is sent back once and then refused, so nothing is saved. A claim the plan asks for that none of the sources supports is left out of the draft and printed for you instead. A section whose assigned sources the library holds none of is not drafted.
- **One library, one key per work.** `.paper/LIBRARY.json` holds every source as a CSL-JSON item: authors as family and given names, its DOI, arXiv ID, PubMed ID or ISBN, abstract and where it came from. `CITATIONS.bib` and `CITATIONS.ris` are written from it, in any script. Research and `pensmith add` find a work they already hold by its identifiers, so it keeps its citekey across runs; a new work gets a key no other work has had. A source with none of those identifiers is left out, since nothing could verify it. An entry you edit in `CITATIONS.bib` by hand is kept as you wrote it; `@comment` blocks and `%` notes are kept too, moved to the top of the file, since entries are written in citekey order. `pensmith add` takes a DOI, an arXiv ID, a URL, a `.bib` or CSL-JSON file, or a PDF, which it identifies by a DOI or arXiv ID printed on it whose work has the PDF's title word for word, or else by a title search whose hit must have that whole title and an author named above the PDF's reference list; only that title line is sent. The PDF's text stays in `.paper/sources/`.
- **Approval gates are on by default.** You approve the outline before drafting and confirm the export before files are written. Only a `--yolo` you type yourself skips those two prompts, and it never waives a citation verdict.
- **One command.** `/pensmith` in Claude Code, or `pensmith` in a terminal, works out the next step from the paper's state and runs it.

## The citation verifier

After a section is drafted, the verifier runs on that section:

| Pass | What it checks | Verdicts | Blocks compile and export? |
|------|----------------|---------|-----------|
| **Pass 1: integrity** | Looks up each cited work by its identifier: a DOI through Crossref, then DataCite, then doi.org (which covers mEDRA, JaLC and the other agencies); an arXiv ID through arXiv; a PMID through PubMed; an ISBN through Open Library. Then compares the entry with the record it gets back: the title word for word (markup, case, punctuation, hyphens and British or US spelling aside; a missing subtitle is fine; every number must match), the first author and every co-author named, the year (within one year) and, for a journal article, the journal. A DOI that resolves is necessary but not sufficient. Then checks whether the work was retracted, from the same record: a retraction, withdrawal or removal notice Crossref lists (Retraction Watch's data among them), PubMed's "Retracted Publication" type, or a "RETRACTED:" title, with OpenAlex as a cross-check (when OpenAlex cannot be asked, verify warns how many citations were checked from their record alone). Reads every Pandoc citation form: `[@key, p. 4]`, `[see @a; @b]`, `[-@key]` and narrative `@key` | `FABRICATED` when no registry holds the work; `MIS-CITED` when it exists but the entry's metadata or one of its identifiers is wrong; `RETRACTED` when the work was retracted; `UNRESOLVED` when no registry answered (retry later), or the entry has no DOI, arXiv ID, PMID or ISBN to look up; `RAW_CITATION` for a DOI, arXiv ID, PMID or `(Author, 2020)` typed as text; `UNPARSEABLE` for a bracketed citation whose key does not parse | Yes |
| **Pass 1: retracted works you cite on purpose** | A paper about a retraction has to cite the retracted work. `pensmith ack <n> <citekey> --reason "…"` records your reason in that section's folder, bound to that key and that work's DOI; `--yolo` never does this | `RETRACTED_ACKNOWLEDGED` | No, but verify, compile and export each warn about it |
| **Pass 1: expressions of concern** | The publisher has published an expression of concern about the cited work, which is not a retraction | `EXPRESSION_OF_CONCERN` | No, but verify, compile and export each warn about it |
| **Pass 3: quotes** | Looks for every quoted span in the open-access PDF of the cited source, found through OpenAlex (and Unpaywall, when a contact email is set: see Configuration): straight, curly and single quotes and block quotes, cited before or after the quote in any form. Every quoted word must appear in the source, in order: case, punctuation, accents and PDF line-break hyphens aside, and a reference marker such as `[12]` or a superscript footnote marker may be left out. A bracketed number or a superscript the quote keeps must stand at the same place in the source, while the source's others may still be left out. One or two quoted words are a term, not a quote, and are not checked; words in brackets are yours and do not count. An ellipsis leaves out words of one sentence (a full stop ends one even with a reference marker after it, as does a heading or a paragraph break), or up to a few lines of text across sentences when both parts have five or more words. Each part around it needs two or more quoted words, or the quote cannot be checked and reads `NOT_FOUND`: quote more, or paraphrase that part. It may leave out a negation only in a clause set off by commas, parentheses or other punctuation, or a whole “not only … but”; the `NOT_FOUND` reason names a negation it may not leave out. A bracketed insertion such as `[the authors]` may stand for up to three words, never a number, and may hold a negation only where those words do. When the source has no open-access PDF, the quote is not checked and the section is marked unverifiable | `NOT_FOUND` | Yes |
| **Pass 3: quotes with no citation** | A quotation of ten or more words that cites nothing. It may quote a source without crediting it, or be your own data (an interview, a participant) or an epigraph, which no source can confirm, so you check it yourself | `UNATTRIBUTED`; the section is marked unverifiable | No, but verify, compile and export each warn about it |
| **Pass 2 / Pass 4: judgment** | Model-assisted claim support and coherence review | Advisory notes | No |

Text that only looks like a citation is flagged too: `ChatGPT (2022)`, `Wuhan (2019)` or a period in brackets such as `(USSR, 1922–1991)` reads as an author-year citation. Write its bracket as `\(` (`ChatGPT \(2022)`), put an identifier in backticks, or write a handle as `\@name`, and the verifier reads it as text. A lifespan after a name, such as `Darwin (1809–1882)`, is not flagged.

**The verdicts are data, and the export is bound to them.** `pensmith verify` records each section's verdicts in its `VERIFICATION.json`, with the version of pensmith that checked them and the hash of the draft it read, of each cited bibliography entry and of the section's acknowledgements; `VERIFICATION.md` is rendered from that record, so editing the report changes nothing compile or done decides, nor the unsupported claims the export confirmation lists. A draft that is empty, or that cites nothing although its plan assigns sources, is not verified. `pensmith compile` refuses any section that is not clean, re-checks a section whose draft, sources, cited entries or acknowledgements changed since it was verified, or that another version of pensmith verified, leaves `.paper/CITATIONS.bib` as it is, and writes `.paper/COMPILE-MANIFEST.json`. Before it exports, `pensmith done` refuses a compiled draft, section, verdict file or cited bibliography entry that changed after compile, then checks every citation and quote of the exact text it exports against the registries again: a work retracted since, or an acknowledgement withdrawn, blocks the export, and a new expression of concern, or a quote whose source text can no longer be read, is reported. Offline (`--offline`) nothing can be checked, so `done` will not export a paper that cites anything.

Edits made after verification are detected with a hash of the draft, so a stale "verified" mark cannot slip through.

## Install

> **You need Node.js 22.12 or newer on your `PATH`, for the plugin too.** The plugin's session-start hook and its bundled `pensmith` command both run with `node`, and Claude Code's native installer does not install Node. In the shell you start Claude Code from, `node --version` must print `v22.12.0` or later.

**Claude Code plugin**

In Claude Code:

```text
/plugin marketplace add ZeusCraft10/pensmith
/plugin install pensmith@pensmith
```

Or from a terminal: `claude plugin marketplace add ZeusCraft10/pensmith`, then `claude plugin install pensmith@pensmith`. This installs the latest release: each release publishes the built plugin, with its bundled CLI, on the repository's `release` branch, so nothing is built or installed with npm.

Until the first release is tagged, or to try unreleased changes, run the plugin from a clone instead. The bundle is not committed, so build it first, then start Claude Code with the plugin loaded: `npm ci && npm run bundle && claude --plugin-dir plugin`.

Then set `ANTHROPIC_API_KEY` in the environment you start Claude Code from (see [Status](#status)).

**Command-line tool**

```bash
git clone https://github.com/ZeusCraft10/pensmith.git
cd pensmith
npm ci
npm run bundle      # builds the CLI bundle (it is not committed)
npm link            # puts `pensmith` on your PATH
pensmith doctor     # checks Node, pandoc, keys and the install
```

## Quick start

In Claude Code:

```text
/pensmith
```

The skill works out the next step from the paper's state, runs it, and asks you the questions it needs answered.

In a terminal, in the folder you want the paper in:

```bash
pensmith
```

The first run starts intake, and each later run advances one step (`pensmith next` does the same).

## Configuration

**Flags** (on any command where they apply):

- `--dry-run`: print what a step would do and run nothing: no model call, no registry lookup, no file written.
- `--estimate`: print the projected token use and cost of what the command would still run, priced with the configured model, and run nothing.
- `--show-prompts`: echo every model prompt to stderr.
- `--yolo`: skip the outline approval and the export confirmation. It never waives a citation verdict, and it refuses to start when the estimated cost of what it would run is more than half of the cost cap.

**Environment variables:**

| Variable | Purpose |
|----------|---------|
| `ANTHROPIC_API_KEY` | Model provider key. Needed for intake questions, outlines, plans and drafts in this alpha, in the plugin and on the command line. |
| `PENSMITH_CONTACT_EMAIL` | Contact address sent to the scholarly registries in the `User-Agent`, and to Crossref and OpenAlex as a `mailto` parameter, as their polite-use policies ask. Unpaywall needs it: without it, Pass 3 finds open-access text through OpenAlex only. |
| `PENSMITH_COST_CAP_USD` | The paper's cost cap in USD (default 5; see [Models and cost](#models-and-cost)). It overrides `cost_cap_usd` in `.paper/config.toml`. |
| `PENSMITH_S2_API_KEY` | *Optional.* Semantic Scholar API key. |
| `GPTZERO_API_KEY` | *Optional.* Enables the AI-likelihood score during `pensmith done`, after a consent prompt. |
| `ZOTERO_API_KEY` | *Optional.* Doctor reports whether a Zotero MCP server is configured; research does not read from Zotero yet in this alpha. |
| `PENSMITH_NO_LLM=1` | Test stub mode: every model call returns placeholder text, which verify, compile and done refuse. A stub run can never be exported. |

[PRIVACY.md](PRIVACY.md) lists every host pensmith contacts, when, and what it sends.

### Models and cost

In this alpha every model call is made with your API key. By default it goes to Anthropic's `claude-opus-5-5`, with the effort and output limit each step needs: drafting and outlining get the most, classifying a source or a claim the least. To choose other models, write a `runtime.json` in pensmith's data folder (`~/.local/share/pensmith/` on Linux, `~/Library/Application Support/pensmith/` on macOS, `%LOCALAPPDATA%\pensmith\` on Windows):

```json
{
  "$schemaVersion": 1,
  "providers": {
    "anthropic": {
      "name": "anthropic",
      "apiKeyEnv": "ANTHROPIC_API_KEY",
      "defaultModel": "claude-opus-5-5",
      "roles": {
        "verify": { "model": "claude-haiku-5-5" },
        "write": { "effort": "high", "maxTokens": 64000 }
      }
    }
  }
}
```

- The first provider listed is the one used. Its `defaultModel` applies to every step a role does not override.
- The roles are `intake`, `research`, `evaluate` (judging search results), `outline`, `plan`, `write`, `revise` and `verify` (the advisory verifier passes). Each takes `model`, `effort` (`low`, `medium`, `high`, `xhigh` or `max`), `maxTokens` (the output limit, thinking included) and `expectedOutputTokens` (what the cost check assumes a call uses).
- An OpenAI-compatible server works too: `"name": "openai"`, with `baseUrl` for one you run (for example `http://127.0.0.1:11434/v1` for Ollama) and `"pricePerMtok": { "input": 0, "output": 0 }` when it costs nothing. `apiKeyEnv` must still name a variable that is set; a local server ignores its value.

Anthropic answers are streamed, so a long draft does not time out, and busy (429/529) answers are retried. An OpenAI-compatible server is sent one request per step and given up to 10 minutes to answer. A step's output limit is lowered to the model's own where that is smaller (16,384 tokens for `gpt-4o` and `gpt-4o-mini`); a `maxTokens` you set is sent as set. An answer cut off at its output limit, or declined by the model, is never saved: the step fails, says why, and can be run again.

Each call's cost is written to `.paper/COSTS.jsonl`, priced from the tokens the provider reports. Before every call pensmith checks that what the paper has spent so far, plus the call's estimate, stays within the cost cap: `PENSMITH_COST_CAP_USD` if set, else `cost_cap_usd` under `[budget]` in `.paper/config.toml`, else $5. A call that would pass it is refused before anything is sent, with exit status 2. The check uses what a call usually costs, not its limit, so the last call can end a little past the cap; the next one is refused. `warn_at_usd` in the same table prints the running total once spending passes it. A model pensmith has no price for is costed at the highest rate it lists, with a warning.

```toml
[budget]
cost_cap_usd = 5.00
warn_at_usd = 2.00
```

## Style Match

Style Match is an **opt-in** feature. Point Pensmith at a folder of your own past writing (`--style-samples <dir>`) and it builds a private, per-paper statistical profile of how you write — typical sentence length, vocabulary density, paragraph shape, common sentence openers — and uses it to help new sections **match your own established voice**.

It is dual-use, and we are direct about that:

- It **improves prose so it reads like your own past writing.** The profile is built from plain statistics — no external model, no network call — and stays inside your paper as `.paper/STYLE.json`.
- It **does not claim to make AI authorship invisible to detectors.** The separate AI-likelihood check reports a score as transparency; Style Match neither changes what that score means nor promises any particular result.
- It is intended for **matching your own voice** — not for passing off someone else's work as your own. The samples you provide should be your own writing.

To keep this honest at the tool level, Pensmith surfaces a transparency notice whenever the same writing samples were already used to style a different paper. That notice always prints; no flag can silence it.

## Architecture

- **The CLI** (`bin/`) holds the whole workflow: state, research adapters, the verifier, compile and export. All network access goes through one HTTP module with SSRF protection.
- **The plugin** (`plugin/`) is what Claude Code installs: a bundled copy of the CLI on the Bash tool's `PATH`, one skill that drives it (including relaying approval questions to you), and a session-start hook that tells Claude the paper's next step when a session opens in a paper workspace. The hook does nothing in other projects.

## Privacy & security

- **Zero export trace.** No metadata stamp, footer or fingerprint is written into exported documents. The disclaimer below is the only disclosure mechanism.
- **Text you give pensmith goes to the model provider.** Intake's opt-in `--pii-redact` redacts personal details in the saved intake answers; the session log redacts keys and personal details. See [PRIVACY.md](PRIVACY.md).
- **Secrets are never logged**, only whether they are set.

## Disclaimer

Pensmith is a structured research-and-drafting assistant for academic writing. It helps you turn an assignment prompt into a sourced outline or, optionally, a full draft, using only verifiable peer-reviewed and configurable academic sources. It includes a citation verifier that re-fetches every cited DOI and flags unsupported claims for human review, and a humanizer pass that improves readability.

This tool is for your own writing, research, and learning. **It is not a guarantee against AI detectors, and it is not a substitute for doing the reading.** Submitting fully tool-generated work as your own is, in many institutions, a violation of academic-integrity policy. You are responsible for the work you submit.
