# Pensmith — Developer Notes

## Layout

- `bin/` — the CLI (TypeScript): `bin/pensmith.ts` dispatches the verbs in
  `bin/cli/`, which call the workflow code in `bin/lib/`.
- `hooks/` — the source of the plugin's one hook (SessionStart).
- `plugin/` — the installed payload. `plugin/dist/` and the copied assets are
  generated by `npm run bundle` and gitignored; the manifest, skill,
  `hooks/hooks.json`, `bin/` shims and README are hand-written. A release
  publishes the built `plugin/` on the `release` branch. See CONTRIBUTING.md.
- `templates/`, `references/` — prompt templates, CSL styles, presets and
  locked user-facing copy, read at run time (and copied into `plugin/`).
- `workflows/` — the older per-verb workflow notes; nothing at run time reads
  them.

## Building

The plugin bundle is not committed, so a fresh clone needs a build before
`claude --plugin-dir plugin`, `npm link` or the tests:

```bash
npm ci
npm run build    # tsc -> dist/ (used by the CLI contract tests)
npm run bundle   # esbuild -> plugin/dist/ (gitignored; the tests and the plugin use it)
```

`npm run build` runs `scripts/prebuild.mjs` first, which writes the
gitignored `bin/lib/version.generated.ts` from package.json.

## Test runner

`npm test` runs `node scripts/run-tests.mjs`. It finds `tests/**/*.test.ts`
itself (no shell glob, so Linux, macOS and Windows run the same files) and
fails when it finds none. What else it does:

- **Isolation.** Each run gets one temp folder holding HOME, the XDG folders,
  LOCALAPPDATA/APPDATA, `CLAUDE_CONFIG_DIR` and the temp folder (TMPDIR, TMP,
  TEMP). Nothing reads or writes your real `~/.claude`, pensmith data folder
  or global paper registry, and the folder is removed after the run with
  whatever the tests left in it (`PENSMITH_KEEP_TEST_RUN=1` keeps it).
- **Cassettes.** It sets `PENSMITH_TEST_CASSETTES=1` (see CONTRIBUTING).
- **No `.paper` in the repository.** The tests run with the repository as
  their cwd. A test that writes a paper's files where the cwd is would put a
  `.paper/` folder there; the run fails when one appears and names the files
  that were running. A `.paper/` left from before stops the run at the start.
- **Counts you can trust.** Each file runs in its own process with
  `scripts/test-reporter.mjs`, which writes that file's results as JSON from
  the test events. The summary line (`# pensmith tests: N files, M tests: …`),
  the `# FAILED:` and `# skipped:` lines and the exit status come from those
  results, not from TAP, so a test that prints TAP-looking text cannot add a
  pass or hide a failure. A file that crashes before reporting, exits
  non-zero, or runs no test fails the run. A file that runs longer than 10
  minutes (`PENSMITH_TEST_FILE_TIMEOUT_MS`) is stopped and fails.

## OneDrive / iCloud / Dropbox / Google Drive

If your repo lives inside a sync folder (the upstream dev folder is `Documents/Github/pensmith` inside OneDrive), exclude `dist/` and `node_modules/` from sync to avoid build-time races. `pensmith doctor` surfaces this warning for `.paper/` workspaces; the same advice applies to the dev tree.

## Quick check

`npm run check` runs prebuild, lint, typecheck, build, the bundle and the tests in one shot.
